# Compute release admission

`check-compute-release` is an offline admission prerequisite in the existing deployment executable. It performs no database/AWS access, launch, secret lookup, image pull or fencing. All services remain parked at zero in unapplied Terraform. See [ADR052](adr/052-protected-compute-release-admission.md) and the unfinished [section acceptance register](configuration-compute.md).

The protected runner supplies these independently managed public trust settings:

| Setting | Meaning |
| --- | --- |
| `SAVEIT_COMPUTE_ACCOUNT_ID`, `SAVEIT_COMPUTE_REGION`, `SAVEIT_COMPUTE_CELL`, `SAVEIT_COMPUTE_STAGE` | Exact target, separately configured from the release |
| `SAVEIT_COMPUTE_RELEASE_PUBLIC_KEY_FILE` | Read-only DER SubjectPublicKeyInfo for one RSA3072–4096 public key; at most2048 bytes, one open file through EOF |
| `SAVEIT_COMPUTE_RELEASE_KEY_SHA256` | Independently reviewed lowercase SHA256 of those exact public bytes |

Managing the pin and file in the same caller-controlled input would defeat this boundary. The runner/operator and signer are trusted custodians; this does not implement their credential lifecycle, hardware custody or separation of duties. No private signing value belongs in arguments, environment examples, Terraform or source control. This command neither creates signing keys nor signs releases.

Standard compact JWS uses header `alg=PS256`, `typ=saveit-compute-release+jwt`, `kid=sha256-<public-key-hash>`. Exact payload fields are `iss=saveit-release`, string `aud=saveit-compute:<account>:<region>:<cell>:<stage>`, integer `iat`/`exp`, canonical nonzero UUID `jti` and `contract`. Lifetime is at most900 seconds, with zero skew and no future issuance. The maintained IdentityModel verifier checks signature, key, issuer, audience and expiration; bounded manual checks additionally enforce claim shape/age. Inline keys, key URLs, extra claims, aliases/duplicates and noncanonical base64url fail. The command accepts no algorithm/key override.

The unsigned synthetic [contract shape](../infra/terraform/ecs-tasks/tests/compute-release-contract.json) binds expected database version, operation/generation, source SHA and all four exact task/image/configuration references, public runtime settings and scoped network/discovery identities. Its invented source/image values are not published artifacts. Web must have no configuration secret; API/worker use exact field/version selectors; relay uses its whole-secret startup ARN/version. Compute generation, workload intake, mTLS, nonroot/read-only runtime, IAM/TLS EFS, liveness and log shape are mandatory. No arbitrary environment, command or extra process is accepted. Image entrypoints inherited by API/web/worker still require trusted registry/config acquisition; a task comparison cannot inspect image contents.

Stdin contains exactly `{"signedRelease":"<compact-JWS>","observations":{"api":{},"web":{},"worker":{},"relay":{}}}`. Each observation has an ECS-shaped `taskDefinition` and optional nonauthoritative `tags`; see the [frozen producer fixtures](../infra/terraform/ecs-tasks/tests/compute-release-observations.json). The complete original input is limited to64KiB/depth24, requires EOF and runs under a10-second CLI deadline. Known service defaults normalize; unknown semantics and extra authority fail. Success/failure output is fixed and content-free. Terraform mocks check the complete producer container JSON against these fixtures, not actual AWS responses.

Short lifetime is **not replay prevention**. Repeated offline inspection is allowed and confers no provider authority. Protected provider operations must acquire trustworthy live metadata and use durable single-use admission plus recorded side-effect intent before any launch/change. A lost acknowledgement requires inspection of that exact operation. Durable admission must survive expiry without authorizing another operation. No caller-supplied `approved` or `fenced` boolean can replace these checks.

[ADR053](adr/053-durable-compute-release-admission.md) now persists the verified operation/hash/key and original signed metadata with one expected-version Parked→Starting transaction. `compute admit-release` consumes the same stdin envelope under a20-second overall deadline, using separate `SAVEIT_COMPUTE_CONNECTION` protected configuration and bounded `SAVEIT_COMPUTE_OPERATOR` attribution. Database TLS/CA, role/schema checks and inert PGOPTIONS rules stay mandatory. This command records supplied-observation intent only, with fixed output; it performs no AWS action. Raw cooperative operator decisions remain privileged primitives, not protected provider approval.

After a lost acknowledgement, use `compute inspect-release <exact-operation-UUID>` to read body-free admission/current-version/phase metadata; do not retry or invent another operation. The retained envelope is accessible only through a separate restricted function for future reconciliation. The database does not verify signatures; later provider code must independently reverify stored signatures against approved trust and immutable bindings, with a deliberate already-admitted expiry policy. The current commands implement no provider reconciliation or launch. Existing journal rows gain no fabricated signed approvals on upgrade; downgrading removes release data and later upgrade does not recreate it.

Current tests cover real PS256/DER verification, all four producer fixtures, target/key/claim/schema substitutions, cryptographic provider-cache lifetime, bounds/EOF, canonical task privileges and native CLI output. Packaged tests generate a fresh synthetic private key only in the fixture process and mount only its public SPKI into a network-disabled nonroot image. Executed source-specific results belong in [progress](progress.md); Docker is unavailable locally. Managed signing/promotion, actual registry/configuration/IAM/network enforcement and whole-cell operation/fencing remain unimplemented or unverified as recorded in the acceptance register.

[ADR054](adr/054-trusted-compute-task-acquisition.md) adds `check-compute-tasks`: a Linux-only read-only prerequisite using the same independent scope/public key settings. Stdin is exactly `{"signedRelease":"<compact-JWS>"}`; no caller-supplied observations are accepted. Original input requires EOF within10seconds, with a40-second overall command deadline. It verifies the release before opening the separate `SAVEIT_COMPUTE_AWS_SESSION_FILE` and uses bounded official STS/ECS SDK requests with native verified regional TLS. Success has fixed output and confers no launch or database authority.

The session file contains exactly `accessKeyId`, `secretAccessKey`, `sessionToken`, `expiration`: temporary ASIA credentials, bounded original32KiB UTF8/EOF, canonical UTC expiration more than60seconds ahead and no more than one hour ahead. Mount it read-only for UID1654 with owner-read permission and no group/other bits. Create/populate it through a protected external custody process; never pass its contents as arguments or commit it. Owned byte buffers are cleared, but immutable SDK-managed credential strings remain sensitive for process lifetime. The loader is not a secret-manager client or human credential lifecycle. Alternate environment/profile/metadata credential sources and endpoint/CA overrides are refused; ambient proxies/telemetry/default region do not control this transport.

STS must identify the exact scoped compute-controller assumed role/account before any of the four signed task revision reads. Caller identity proves this temporary session's provider identity, not human separation or transitive IAM isolation. Each complete original task response is bounded and validated before SDK model fields can discard unknown semantics. No registry image contents, service ownership, network reachability, configuration payloads, running tasks or ENIs are verified by this command; these remain controller prerequisites.

`check-compute-parked-services` extends that read sequence with exactly one scoped cluster and the four full scoped service ARNs, using the same signed-release-only stdin/trust/session settings. See [ADR055](adr/055-trusted-parked-service-acquisition.md). It requires the initial zero-count service/task/network/registry/deployment contract and no extra authority; its fixed success message explicitly confers no ownership handoff, launch or fencing. It cannot admit subsequent live revisions or infer task/ENI absence from counts. Limits are40seconds overall,10seconds input EOF,5seconds per complete provider read,64KiB cluster and512KiB four-service responses. Unknown returned semantics fail closed pending review; managed response/default compatibility remains unverified.

`check-compute-images` continues the same initial read sequence with four exact ECR platform manifests and their hash/size-bound configuration blobs. See [ADR056](adr/056-trusted-image-configuration-acquisition.md). It accepts the same signed-release-only stdin/trust/private temporary-session file, allows100seconds overall/90seconds acquisition/10seconds input EOF and retains5-second complete-read deadlines. No registry URL, token, manifest, observation or configuration is accepted from stdin. One SDK registry bearer response is checked against the independently derived own endpoint; its Basic credential is used only for the four bound configuration GETs, never redirect/download URLs. It remains a read-only prerequisite, with fixed body-free output.

Configuration requires the known Linux/amd64 image, UID1654, working directory, entrypoint/command, environment, volumes/health and exact approved source labels. Original manifest/configuration bytes bind their digests; canonical layer descriptors are inspected without fetching layers. These checks establish neither source-to-binary provenance nor signature/vulnerability/license/promotion approval. Initial platform support excludes indexes/attestation selection, foreign layers and nongzip compression. Token/envelope caps are local fail-closed limits and managed ECR compatibility remains unverified. Managed strings/parsed copies can retain sensitive drift/credential data until process exit; clearing owned byte buffers is not full memory erasure.

`check-compute-configuration` extends the full sequence with three fixed Secrets Manager reads using only each signed full ARN/version UUID. See [ADR057](adr/057-trusted-private-configuration-cohort.md). Same signed-release-only stdin, independent trust and private session file; no private payload/endpoint/override enters stdin. Limits:120seconds overall/110seconds acquisition/10seconds stdin EOF/5seconds per complete read; raw envelopes512KiB, original decoded payloads64KiB. Exact ARN/friendly Name/UUID, raw field vocabulary and strict carriers fail closed; mutable labels never select versions.

The cohort requires matching configured database targets/exact runtime users, pinned database roots, canonical API/relay names, pinned offline chains/receiver pins and separate transport/protector/anchor keys. Expired retired protectors remain supported. API-root custody comes from the approved immutable relay version. No private result or live database/Okta/provider-write check is returned. Use reviewed public-only `saveit-trust`, `saveit-relay-trust` and `saveit-client-trust` image contexts; never include private keys. All counts remain zero; ownership/launch/fencing remain unfinished.

`check-compute-security-groups` requires the optional signed `network.bindings` extension before provider contact. See [ADR058](adr/058-bound-security-group-acquisition.md) and the [synthetic shape](../infra/terraform/runtime-endpoints/tests/compute-network-graph.json). Old signatures remain inspectable but cannot authorize network acquisition/future launch. New maps bind additional SG/DB-subnet/route/endpoint IDs, policy-hash metadata and an S3 prefix. This stage observes only the complete initial13-SG graph through one fixed VPC-scoped EC2 query after the19 earlier reads; no name/tag-selected replacement is approved. Policy hashes/other references are metadata, not observed policy/route/S3-owner evidence.

Same stdin/session/public trust and fixed output rules;130seconds overall/120seconds acquisition/10seconds input EOF/5seconds per complete read,512KiB query XML. Extra/duplicate/foreign/unknown/CIDR/IPv6/peering/range/pagination authority fails closed. SG aggregation and Resolver exceptions prevent attachment/DNS/fencing claims. Native/managed compatibility and remaining full-network/controller gates stay explicit.

The acquisition runner expects protected regular files on local storage for the session, public key and public trust inputs. The asynchronous deadlines do not interrupt a synchronous open on a stalled mount or a special file. The native fixture also has a separate bounded process watchdog.

`check-compute-routes` adds the five fixed reads in [ADR059](adr/059-bound-private-route-acquisition.md) after the security-group check: exact VPC, both DNS flags, all four signed private subnets and the complete route-table inventory. It requires four explicit associations, a local-only main table, original active local routes and one signed application-only S3 prefix route. Same protected inputs and fixed output;160seconds overall/150seconds acquisition/10seconds EOF/5seconds per complete read. DNS flags and route references confer no Resolver policy, endpoint policy, attachment, ownership or launch evidence.

`check-compute-endpoints` uses the same protected inputs and adds the VPC endpoint inventory and exact S3 managed-prefix read. Review the six declared policy digests from the fully bound runtime-endpoints root before including them in the signed release. The verifier compares those digests to the normalized provider readback, and checks service, VPC, endpoint type, network references and regional AWS prefix ownership. Managed IAM evaluation and independent attachment checks remain deployment gates. [ADR060](adr/060-bound-private-endpoint-acquisition.md)

`check-compute-network` additionally checks the VPC's associated DHCP option values and the independent inventory of interface endpoint attachments. It requires regional AmazonProvidedDNS defaults and matches the ten reported interfaces against approved endpoint, subnet and group references. Live DNS resolution and Resolver policy remain separate checks. [ADR061](adr/061-bound-dhcp-and-endpoint-interfaces.md)
