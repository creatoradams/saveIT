# SaveIT production-readiness reassessment

**SaveIT is a tested local preview, not a production release.** Credential-free engineering remains before account setup becomes the next dependency. The [current progress/evidence](progress.md) is authoritative; historical checkpoints are preserved in [delivery history](progress-history.md). The full [enterprise backlog](backlog.md) and all 146 [inventory entries](feature-parity.md) remain open according to their individual status.

## What is ready to exercise locally

The core documentation/inventory workflow persists in real PostgreSQL with live membership/organization checks, 28 forced-RLS tables, scoped foreign keys and atomic business/history/audit/outbox/queue writes. Search is a restricted derived PostgreSQL projection that rechecks current authority/source. Browser flows include conflicts, history/comparison/restoration, scoped folders and reviewed templates.

Production-mode containers, seed-free deployment/provisioning, isolated access operations, bounded configuration/health tools, the relay mTLS path and a synthetic logical database/key recovery drill have CI evidence. The Okta adapter is implemented and tested with a synthetic external identity provider. Cloud definitions are mock-tested and unapplied. [Progress](progress.md) gives exact source/run links and current lower security findings; passing tests do not establish production safety or capacity.

Accounts, region/residency, budget, licensing, regulated-data scope and support ownership require decisions before provisioning. Never send secrets in chat or put them in Terraform, CLI arguments, Git or test evidence.

## Specific unresolved boundaries

- ADR053 records verified release intent with expected-version/single-use admission and exact-operation inspection. A stored row is a trusted operator assertion, not provider authority: future reconciliation must independently reverify its signature/bindings and acquire trustworthy live metadata. Side-effect intent, privileged-writer exclusion, ownership handoff and launch/fencing remain unfinished.

- [ADR052 release admission](compute-release-admission.md) checks independently pinned short-lived signed metadata and exact four-task contracts offline. It does not acquire provider observations or establish replay prevention, protected signing/promotion/population, launch/change authority or fencing; those remain unfinished. A trusted runner's approval key/pin cannot come from the same caller-controlled input.

- The separate relay identity root reserves exact whole-secret ARN/UUID/via-Secrets-Manager/account/context authority for the implemented ADR044 task loader. Execution owns exact image/own-log authority. Null bootstrap denies all AWS actions; bound metadata is not launch approval. ADR045 optionally admits the distinct callers in endpoint filters. ADR046 separately opts into its own group, private registry and declared web/relay/API paths without an IAM grant or task attachment. Initial null compatibility is not safe withdrawal/failover; it can restore direct declarations and protected registry removal can block a transition.
- **Pre-apply compatibility gate:** direct regional Logs customer kms:CallerAccount availability is unverified. The retained restrictive key policy may deny real service calls when context is absent. Obtain managed context/DescribeKey/PutLogEvents and wrong-scope denial evidence, or separately review an account-bound replacement before apply. Do not infer compatibility from fabricated mock contexts.
- All infrastructure roots are unapplied. Mock plans and declared cross-root contracts do not prove actual/transitive IAM, SG/DNS drift, mounts, injection, ingestion or service behavior. Trusted administrators/custodians can change policies; custodian restrictions are not exclusive payload-writer proof. [ADR049](adr/049-offline-relay-task-preflight.md) checks supplied relay task structure/image/configuration references offline; trusted acquisition, signatures/promotion, override prohibition and launch/change authority remain unfinished.
- Optional ADR050 intake verifies workload JWTs over native TLS; null remains legacy unauthenticated bootstrap. Actual Cognito issuer/claims/rotation and IAM enforcement remain unverified. User/tenant authority still comes from protected sessions and live database checks. ADR051 coordinates cooperative core/worker admission and generation checks; CoreQuiescent excludes privileged migration/access writers and downstream buffers. Exact process fencing and protected whole-cell ownership remain unfinished.
- The web SDK is bundled by Next and not individually identified by current image SBOM cataloging. Locked npm audit is separate evidence; final-bundle dependency inventory completeness remains release-assurance work.
- ADR054's read-only STS/task acquisition uses a private temporary-session file and fixed verified regional transports; ADR055 adds exact initial parked-cluster/service metadata. Synthetic checks are not live role/IAM or task/ENI-absence proof; later service changes, network/image/configuration acquisition, controller side effects, explicit ownership handoff and process fencing remain unfinished. No account credentials are needed for these tests.
- ADR056 adds ECR platform-manifest/configuration hash and inherited startup checks; native verification is pending. Original layer bytes, binary provenance, signatures, vulnerability/license approval and protected promotion remain separate requirements. Registry token limits and supported manifest/compression/default shapes need managed compatibility evidence. No launch authority follows from its fixed success output.
- The recovery drill retains the same cluster/roles/CA. It does not establish managed/PITR/offsite/KMS recovery, achieved RPO/RTO or asset/deletion recovery.
- Four medium JavaScript findings and lower image findings remain tracked in progress. Synthetic tests and agent reviews do not replace independent penetration/cryptographic/deployment assessment. Windows full-suite PostgreSQL backend-exit limitations remain separate from verified Linux execution.
- Current live identity configuration supports one issuer mapped to one SaveIT tenant. Multi-customer connections, SCIM/SAML/lifecycle, delegated permission administration and customer onboarding require further implementation and evidence.

## Proposed first release

An invitation-only documentation/inventory pilot with one real Okta connection, explicitly approved users/data and multiple authorized organizations is a proposal, not a reduction of enterprise scope. Staging stays synthetic until applicable gates pass. Vault/password/OTP, uploads, connectors, rich collaboration, portals, mobile/extensions, discovery, AI and other absent features must remain visibly unimplemented.

Do not publish a percentage-complete estimate, launch date, vendor-parity claim, SLO or compliance claim without evidence. [Completion register](completion-register.md) separates implemented code from remaining scope. Earlier readiness wording is available at the [pre-cleanup snapshot](https://github.com/creatoradams/saveIT/blob/3711107/docs/production-readiness.md); it is historical, not current status.
