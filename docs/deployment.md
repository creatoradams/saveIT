# SaveIT release artifacts and local production verification

[ADR 034](adr/034-private-runtime-service-endpoints.md) and [runtime-endpoints](../infra/terraform/runtime-endpoints/README.md) define only private AWS service paths and exact endpoint filters, without running workloads or populating configuration. Bind the updated separated foundation network output and identity metadata. The new S3 gateway targets only application routing. Before real launch inspect unfiltered routes/propagations/service endpoints, SG/NACL and DHCP/resolver drift, then verify actual role/version/presigned-image/log paths. Pinned provider data hides several route classes; mocks do not prove isolation. Encrypted web/API transport, trusted forwarding/CA delivery, restricted Okta egress, ingress/services and protected deployment operations remain gates.

[ADR 033](adr/033-guarded-application-task-definitions.md) and [ecs-tasks](../infra/terraform/ecs-tasks/README.md) add unapplied application task definitions only. Images declare an owned UID/GID-1654 mode-0700 `/var/saveit/runtime` VOLUME for read-only-root scratch; the worker health file uses it. API image/task readiness executes `dotnet SaveIT.Api.dll --healthcheck`, which contacts only direct loopback, rejects mixed arguments and does not start a host/DB client itself. Only API receives the checked `/var/saveit/keys` IAM/TLS EFS volume. Require exact concrete EFS/log identity bindings in addition to readiness booleans. Operational log buffers are bounded/nonblocking and can lose events; PostgreSQL audit remains separate. Task launch networking, HTTPS/authenticated encrypted inter-service transport, trusted forwarding, CA delivery, services and protected operators/promotion remain pre-launch gates.

ADR 032 adds unapplied private image/operational-log stores and an optional exact own-log-key execution binding. See [artifact-stores](../infra/terraform/artifact-stores/README.md) for the metadata-only sequence and trust/retention limits. Encrypted PutLogEvents needs the own-key via-Logs caller binding as well as service key permission; future compute must require log-key-binding-ready and EFS-binding-ready. No images were published, logs collected, signatures promoted or cloud tasks run. Managed authorization, ingestion/redaction/alerts, immutable audit archival, networking and deployment remain gates.

The application is still a preproduction system. See [production readiness](production-readiness.md) and [ADR 022](adr/022-production-release-foundation.md). This guide describes artifacts/tooling and synthetic verification; it does not authorize cloud provisioning or use of customer credentials/data.

## Separate identities and migration

1. An authorized cluster administrator reviews `infra/postgres/bootstrap-roles.sql`. It creates safe fixed roles if absent and refuses elevated preexisting roles. There are no passwords, cloud calls or tenant records in that script.
2. Create an empty UTF8 PostgreSQL database owned by `saveit_migration_owner`. Grant that role only to a separately controlled deployment login. Provision workload logins/secrets separately. Never grant deployment ownership to the API/worker, including NOINHERIT reachability.
3. Provide `SAVEIT_DEPLOYMENT_CONNECTION` through protected job configuration with `SSL Mode=VerifyFull` and the trusted root certificate. No default connection or credential argument is accepted. `dotnet SaveIT.Deployment.dll migrate` applies forward migrations, validates the exact release boundary and grants runtime read access only to the schema-history marker column. Inspect migration SQL and rehearse upgrades before a real deployment.
4. Prepare a private bounded JSON manifest shaped like the synthetic `tests/production/provision.json`, using explicitly chosen tenant/member/org IDs and the actual verified issuer/subject. Do not commit it. `dotnet SaveIT.Deployment.dll provision <protected-file-path>` creates one initial tenant/administrator/org atomically. It never upserts existing authority; duplicates fail and require review. `operator` is declared privileged-operator attribution, not proof of an authenticated operator session.

The local test-only connection escape is `SAVEIT_DEPLOYMENT_ALLOW_LOOPBACK=true`; runtime equivalent `Deployment__AllowLoopbackDatabase=true`. Both permit plaintext only for literal loopback/localhost, never a remote service or multi-host connection. Real deployment uses certificate/hostname-verified TLS. Shared connection normalization explicitly disables GSS transport and refuses an explicit GSS Require setting, so default/ambient negotiation cannot replace the intended certificate TLS path. The packaged fixture does not use the escape.

Owner policies are explicitly restricted to the isolated migration owner. They do not replace tenant policies, remove forced RLS or grant runtime owner/DDL access. Production functions/backfill privileges must be verified on the chosen managed database before deployment. Development seed databases are not automatically adopted into this ownership model.

## Images and runtime configuration

Build from the repository root:

```sh
docker build -f infra/containers/dotnet.Dockerfile --target api -t saveit-api:review .
docker build -f infra/containers/dotnet.Dockerfile --target worker -t saveit-worker:review .
docker build -f infra/containers/dotnet.Dockerfile --target deployment -t saveit-deployment:review .
docker build -f infra/containers/web.Dockerfile -t saveit-web:review .
```

All four run as nonroot and use digest-pinned base images. Keep build locks tracked, audit/patch bases at release and promote the same reviewed images across environments. Never run `npm run dev` or the embedded development database in a deployment.

API: supply `ConnectionStrings__App`, explicit `AllowedHosts`, `DevelopmentIdentity__Enabled=false`, the real `Identity__Okta__*` settings from ADR 010, and persisted certificate-protected key configuration. It refuses unconfigured nondevelopment identity, dev identity, insecure remote database TLS, wrong schema and elevated/owner/DDL runtime roles. The key directory must be writable only by the application identity and survive container replacement. Optional `Identity__PreviousKeyCertificates__0__Path`/`Password` (at most four) retain prior private certificates for a controlled decryption window; expiry does not prevent decrypting old keys. Do not share rings across environments. This is not automated key rotation/recovery.

Configure `Deployment__TrustedProxies__0` and/or `Deployment__TrustedNetworks__0` with only actual ingress peers/subnets, backed by restricted network access. Forwarded protocol is processed before secure-cookie CSRF; an untrusted header alone must not change HTTPS authority. Unconfigured trust is disabled. A trusted network is not a replacement for service security groups and private upstream access. End-to-end deployed TLS/Host behavior still needs staging verification.

Web: set runtime `SAVEIT_API_ORIGIN` to the private API origin, `SAVEIT_PUBLIC_ORIGIN` to the exact public HTTPS origin, and `SAVEIT_OKTA_ISSUER` to the same validated issuer. These are server-only settings. The standalone server accepts `HOSTNAME`/`PORT` (image defaults 0.0.0.0/3000). Public Host validation applies to application/API requests; the generic readiness path supports load-balancer probes. Script nonces require dynamic/no-store rendering. Inline style support remains; broader CSP/client accessibility review is still needed.

Worker: supply `ConnectionStrings__SearchWorker` and the explicit bounded `SearchWorker__Tenants__0...` allowlist. Set a private writable `SearchWorker__HealthPath` if desired (default temp directory). Health command: `dotnet SaveIT.Workers.dll --healthcheck`. It must become healthy before failure-transition tests are meaningful. Committed progress updates health during long tenant cycles; unresolved tenant failures or a stale/malformed snapshot return nonzero. Startup/once/rebuild/replay use the same restricted role/TLS/schema checks. The probe is not a promise that the queue has no dead letters or that a delivery SLO is met.

`/health/live` reports API process liveness; `/health/ready` checks connectivity, runtime role and required forced-RLS schema/release (Production). The web `/health/ready` checks its private upstream. Dependency failure produces generic 503 without internal details. Health does not grant record access or bypass current membership/read audits.

## Restricted private access operations

ADR 025 adds `dotnet SaveIT.Deployment.dll access apply <private-manifest>` and `access inspect <private-manifest>`. These use only `SAVEIT_ACCESS_CONNECTION`, never the migration-owner connection. Supply verified remote TLS/root configuration through a protected operator job. The local synthetic exception is separately opt-in with `SAVEIT_ACCESS_ALLOW_LOOPBACK=true`; it does not allow insecure remote hosts. No credential belongs in arguments, manifests, Git or chat.

An authorized DBA creates a separate non-elevated NOINHERIT login and grants only the fixed NOLOGIN `saveit_access_operator` role. Do not give it owner/API/worker membership, schema CREATE or direct core/protocol table/column privileges: the command guard rejects these paths. Fixed roles are cluster-global, so membership reaches every database granting these functions unless separately restricted by CONNECT/per-database boundaries. Isolate different operator trust domains with separate roles/clusters; a manifest tenant ID does not restrict the credential's authority. Actual credential issuance/rotation, human operator authentication and managed-database verification remain production gates.

Use the sanitized `infra/postgres/access-{create,change,inspect}.json.example` files. Keep real manifests under ignored `.local/operator` or a private job mount readable only by the operator identity. The CLI reads at most 8,192 characters, rejects unknown fields and uses checked parameters. `operator` is bounded declared attribution; audit separately records actual PostgreSQL `session_user`. It does not prove a human IdP identity. No reasons, record content or secrets belong in attribution.

- `create`: existing tenant/org, new member GUID, expectedVersion 0, exact verified HTTPS issuer/externalSubject, displayName and initial Viewer/Editor role. No email matching or provider role/tenant elevation. Creates an active member without organization-administration capability.
- `active`: current expectedVersion plus enabled true/false. Actual transitions advance AccessVersion and SessionEpoch; reactivation requires fresh sign-in.
- `grant`: current expectedVersion, organizationId and role Viewer/Editor; null/omitted role removes that grant. Live role checks continue with the existing cookie.
- `capability`: current expectedVersion and enabled true/false changes organization-administration capability. Rename still requires current Editor.
- `inspect`: tenantId/membershipId/operator and optional afterOrganizationId. Commits a read audit before returning at most 50 grants/current flags/versions and bounded pending-response diagnostics. Pages are live observations; output alone grants no authority.

Changes, tenant access audit and separate metadata-only control event commit atomically. Search does not consume this control outbox; generic delivery remains unimplemented. No automatic retry follows an uncertain commit. Inspect current versions and protected audit before preparing another command. Automatic creator grants also advance AccessVersion.

OnCompleted closes durable records using separate bounded client-pool capacity; failed persistence retries only known-finished completion. Operator acknowledgement follows drain and commit. The five-second gate/drain timeout rolls back with access unchanged. Pending records have no expiry/force-close path. An uncertain record can block changes until privileged instance-fencing/recovery is established. An unreachable instance or negative health probe alone is not proof that response writes have stopped. Managed orphan-recovery commands, human access brokering and automatic fencing remain unimplemented. Never clear records based on age. Pruning removes only bounded already-closed records older than seven days. Separate pools do not reserve PostgreSQL server slots; operating headroom is required.

Stop older API versions before rollout; epoch-less cookies must reauthenticate. Restore/failover that might lose committed response records requires fencing all old API instances before operator acknowledgements resume. Future exports/files/streams need equivalent treatment. API completion cannot recall Next.js/nginx/network/client buffers. The synthetic recovery fixture stops its API/worker; it does not prove managed fencing/failover or production offboarding readiness.

## Synthetic packaged test

On Linux with Docker/Compose, OpenSSL, Node24 and Chromium available, build the four images above using `:test` tags, and also build the `identity-fixture` target as `saveit-identity-fixture:test`. Then run `bash scripts/test-production.sh`. The production-artifacts CI workflow does this in an isolated runner.

The script creates short-lived synthetic CA/TLS/key-protection material under ignored `.local/container-fixture`, starts real PostgreSQL with verified TLS, bootstraps the separate roles, runs the actual deployment image without seeding, provisions two synthetic tenant/org scopes and starts readonly nonroot application containers behind TLS. It checks actual signed OIDC/PKCE, secure session cookies, persistence, populated foreign scope denial, prior-key/cookie recovery after restart, CSP nonce/no-store, positive-to-negative API/worker health and restricted operator downgrade/offboard/reactivate/old-cookie-denial/fresh-sign-in behavior. No official provider account is involved. Browser TLS uses a fixture-only certificate-error exception, while curl and database clients verify their fixture CA.

Only the dedicated test target includes the synthetic provider. It refuses environments other than ContainerTest; never deploy that target as identity. Test CA/PFX/private keys, database files, traces and screenshots must remain ignored and must never enter app images or Git. Current results and limitations belong in progress after actual execution.

## Isolated recovery rehearsal

ADR 023 extends the packaged tests with a synthetic logical recovery drill. The recovery browser flow creates current/revision content, retains its session and invokes `scripts/rehearse-recovery.sh`. That helper targets only the disposable `saveit-release` Compose graph. It stops API/worker writers, dumps the database, snapshots persisted keys and both current/prior protectors, checks backup hashes and restores into `saveit_recovery` and a separate `recovered_keyring` volume. Original targets are retained. Protected-table/migration counts must match before restarting writes; the normal restricted worker rebuilds search and the same images start under the normal runtime guards. The browser checks its existing cookie, exact snapshots, tenant denial, rebuilt search and a new audited write.

Run this only through the synthetic packaged suite. It is not a general production restore tool. Backup/key material and test evidence stay under ignored `.local`/test output paths. This drill retains the same cluster/roles/CA and uses a fixture administrator to preserve object ownership/grants. It does not establish independent-cluster or managed point-in-time restoration, offsite/immutable backups, KMS recovery or achieved RPO/RTO. Execution status is recorded in progress after actual Linux CI, not inferred from these definitions.

## Injected session-key protectors

The unapplied [workload-identity root](../infra/terraform/workload-identity/README.md) now defines isolated task/execution roles and pinned configuration-secret references under ADR 031. It creates metadata only, never secret values or tasks. Its fail-closed bootstrap must later bind the reviewed EFS ring before compute; actual protected population/injection, workload authorization, scheduler/PassRole, ingress/egress, promotion and managed recovery still need implementation/verification. Trusted metadata administrators can replace payloads via UpdateSecret as well as change policies. This is no product vault or deployment approval.

ADR 029 supports either `Identity__KeyCertificatePath` or `Identity__KeyCertificateBase64`, exactly one per current protector. Supply `Identity__KeyCertificatePassword` separately through protected configuration. Retired entries (at most four) likewise select `Identity__PreviousKeyCertificates__0__Path` or `__Base64` plus `__Password`. RSA private keys must be at least 2048 bits; current certificates must be presently valid. The decoded PFX limit is 64 KiB, with host/secret-store limits possibly smaller. Old weak/non-RSA or conflicting configurations now fail startup. No secret value belongs in Terraform, a tracked example, CLI arguments, logs or a configuration dump. The sanitized root example leaves both sources empty.

Treat the Base64 value as secret material: encoding does not encrypt it. Imports use ephemeral native key storage and clear owned decoded buffers. The in-process private key and managed configuration/environment strings still hold secrets; restrict task identity, diagnostics/exec, secret references and filesystem/metadata access. The existing persisted protected ring is still required and must survive replacement. This option does not fetch Secrets Manager, provision an EFS/key store, configure multiple instances, automate rotation or prove key recovery. Packaged synthetic file/injection/replacement/old-cookie/recovery checks must pass before claiming that subset; actual cloud IAM/KMS/key lifecycle remains unverified.

ADR 030 adds an unapplied [private key-storage definition](../infra/terraform/key-storage/README.md), with two private EFS targets and a dedicated IAM/TLS access point for the exact API task role. It exports future task-volume metadata and `/var/saveit/keys` mount intent; no task mounts it yet. Use only the corresponding cell/environment ring and protector set. Automatic backup enrollment does not implement reviewed retention/vault/restore/fencing. Full compute/secret-reference wiring and actual managed multi-replica/key/session/recovery verification remain required.
