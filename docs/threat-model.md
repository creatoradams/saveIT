# SaveIT threat model and release risks

Updated 2026-10-29. Scope: the local core, synthetic data and unconfigured Okta adapter. Owners: project maintainers. Reassess each added endpoint, consumer, identity adapter, and data classification.

## Data and trust boundaries

Public: product branding and health status. Internal: organization/asset metadata. Confidential: IT documentation, revisions, relationships, audit identities. Restricted: future passwords, OTP seeds, keys, recovery and export material. Treat all tenant content as untrusted. No real credentials belong in this prototype.

Boundaries: browser ↔ same-origin Next proxy ↔ ASP.NET session/policy ↔ restricted PostgreSQL API role; a separate tenant-configured worker role reads the core search-source contract and writes only derived projections/consumer receipts. Migration owner credentials are separate. Future distributed search, attachment, vault, extension, discovery, and AI boundaries require further threat models. The public Git repository contains source and synthetic fixtures only.

## Release-risk register

All entries below block a production/enterprise-ready claim. Separate automated code reviews are recorded in the review report; no external penetration assessment, SOC 2, production security guarantee, achieved SLO or vendor parity is claimed.

1. **Identity**: the Okta OIDC adapter and exact subject mapping are implemented with signed synthetic tests. Real issuer/app configuration, assignment/MFA/assurance verification, lifecycle/SCIM/SAML, service tokens, break-glass, IdP session revocation, operated key storage/recovery, HTTPS and trusted proxy policy remain absent/unverified. The user selected Okta; no live tenant is connected.
2. **Authorization**: no group/relationship denies, permission administration, cross-account sharing, OpenFGA, or concurrent revocation barrier. Current guarantees cover the implemented organization roles and subsequent requests.
3. **Audit**: successful changes and document-body/revision reads are durable; authentication, denied attempts, metadata reads, permission administration, support/emergency/export activity and failed-operation auditing are incomplete. No separate immutable archive, retention, SIEM export, or gap detection exists.
4. **Events/operations**: search-v1 consumption has tested atomic queue discovery/idempotency/replay/retry/dead letters and rebuild commands. Production enqueue-function ownership/forced-RLS/backfill authority, generic external dispatch, Temporal, operational administration/immutable replay audit, metrics/traces/alerts, quotas, backups and recovery drills remain pending. Queue enqueue failure intentionally blocks core writes. Search completion receipts never mark global outbox delivery. Do not delete receipts or manually mark events delivered to consumers that have not handled them.
5. **Credentials/AI**: vault remains absent. Resolve key ownership/recovery and independent crypto review before real credentials; AI is disabled, with no provider or paid service provisioned.
6. **Supply chain**: pinned npm/NuGet lockfiles and CI dependency audits establish a baseline. SBOMs, secret/SAST scanning at organization scope, signed images, release provenance, patch response and penetration testing remain required. Local SDK 10.0.401/runtime 10.0.12 requires servicing update before release.
7. **Data lifecycle**: plain-text document and asset metadata restoration check current access and preserve history; directory archival retains records. Deletion recovery/retention, import/export, data residency, support access, backup-restore access/deletion checks and legal obligations remain unresolved.
8. **UX/performance**: automated axe/keyboard/responsive tests cover a few flows; real screen-reader testing, WCAG 2.2 AA review, representative IT-user research, virtualization, saved views, command palette, and documented load tests remain.

## Review checklist for the next slice

Keep current search authority/stale-index/outage and queue atomicity/late-commit tests for every extension, including future OpenSearch, facets/counts/autocomplete, filenames and AI retrieval. Never use indexed ACLs as final authority. Preserve document recovery (ADR 007), both relationship endpoint FKs/lifecycle tests (ADR 008), directory/asset history (ADR 009), signed identity denial tests (ADR 010) and reachable-role/queue controls (ADR 011). Organization administration must define trusted actions and revocation consistency before exposing permission changes. Private attachments require scan/quarantine, isolated parsers, SSRF controls, authorized delivery and retention. Production rollout requires reviewed migrations and an actual isolated backup restore test.
