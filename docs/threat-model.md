# SaveIT threat model and release risks

ADR 032 adds unapplied registry/log stores and exact optional execution log-key binding. Repository deny policies isolate image readers/publisher/control changes and preserve images/tags; administrators can change those policies, so this is no tamper-proof signing/promotion boundary. Per-log KMS scope supports direct regional Logs service and separately authorized forwarding. Bound execution policies add only own-key/via-Logs/context crypto and separate key description, retain configuration-secret constraints and forbid configuration-key reuse. No task/query authority is added. Null binding is bootstrap only; future encrypted compute needs both log and EFS readiness gates. Finite operational retention can delete events and is not immutable tenant audit archival. Actual IAM/PutLogEvents, redaction/collection, privilege drift, retention/key availability and operated recovery remain verification gates.

Updated 2026-10-31. Scope: the local core, synthetic data and unconfigured Okta adapter. Owners: project maintainers. Reassess each added endpoint, consumer, identity adapter, and data classification.

## Data and trust boundaries

Public: product branding and health status. Internal: organization/asset metadata. Confidential: IT documentation, revisions, relationships, audit identities. Restricted: future passwords, OTP seeds, keys, recovery and export material. Treat all tenant content as untrusted. No real credentials belong in this prototype.

Boundaries: browser ↔ same-origin Next proxy ↔ ASP.NET session/policy ↔ restricted PostgreSQL API role; a separate tenant-configured worker role reads the core search-source contract and writes only derived projections/consumer receipts. Migration owner credentials are separate. Future distributed search, attachment, vault, extension, discovery, and AI boundaries require further threat models. The public Git repository contains source and synthetic fixtures only.

## Release-risk register

All entries below block a production/enterprise-ready claim. Separate automated code reviews are recorded in the review report; no external penetration assessment, SOC 2, production security guarantee, achieved SLO or vendor parity is claimed.

1. **Identity**: the Okta OIDC adapter and exact subject mapping are implemented with signed synthetic tests. Real issuer/app configuration, assignment/MFA/assurance verification, lifecycle/SCIM/SAML, service tokens, break-glass, IdP session revocation, operated key storage/recovery, HTTPS and trusted proxy policy remain absent/unverified. The user selected Okta; no live tenant is connected.
2. **Authorization**: no group/relationship denies, permission administration, cross-account sharing, OpenFGA, or concurrent revocation barrier. Current guarantees cover the implemented organization roles and subsequent requests.
3. **Audit**: successful changes and document-body/revision reads are durable; authentication, denied attempts, metadata reads, permission administration, support/emergency/export activity and failed-operation auditing are incomplete. No separate immutable archive, retention, SIEM export, or gap detection exists.
4. **Events/operations**: search-v1 consumption has tested atomic queue discovery/idempotency/replay/retry/dead letters and rebuild commands. Production enqueue-function ownership/forced-RLS/backfill authority, generic external dispatch, Temporal, operational administration/immutable replay audit, metrics/traces/alerts, quotas, backups and recovery drills remain pending. Queue enqueue failure intentionally blocks core writes. Search completion receipts never mark global outbox delivery. Do not delete receipts or manually mark events delivered to consumers that have not handled them.
5. **Credentials/AI**: vault remains absent. Resolve key ownership/recovery and independent crypto review before real credentials; AI is disabled, with no provider or paid service provisioned.
6. **Supply chain** — Pinned npm/NuGet lockfiles, CI dependency audits, source and reachable-history scanning, and final image SBOMs and vulnerability scans establish the repository baseline. Release signing, protected promotion, organization-level scanning, complete bundled dependency inventory and penetration testing remain open. Use the source-bound results in [progress](progress.md) to check current advisories and runtime servicing.
7. **Data lifecycle**: plain-text document, asset and directory restoration check current access and preserve history/lifecycle. Deletion recovery/retention, import/export, data residency, support access, backup-restore access/deletion checks and legal obligations remain unresolved.
8. **UX/performance**: automated axe/keyboard/responsive tests cover a few flows; real screen-reader testing, WCAG 2.2 AA review, representative IT-user research, virtualization, saved views, command palette, and documented load tests remain.

## Private operator and response-drain boundary

ADR 025 implements the bounded operator access/drain subset; earlier references to absent in-flight permission revocation describe the pre-025 baseline. Durable pending response records survive lost database sessions, and only actual server OnCompleted can close them. Registration/inspection shared gates and the operator exclusive gate use fresh VOLATILE READ COMMITTED observations; operator row locks follow drain. Exact epoch/subject checks precede protected work and cookie output; reactivation cannot revive old sessions. Access/grant/version/audit/control events commit atomically, without historical content/reasons in metadata. All 28 tenant tables retain forced RLS and qualified source FKs. Runtime/worker cannot reach operator roles/functions or protocol table/column reads/writes, including PUBLIC/NOINHERIT paths.

An operator database credential is authority across databases granting its cluster-global role; declared attribution/manifest tenant IDs do not scope or attest a human identity. Separate trust domains/database reach and secure credential issuance remain deployment responsibilities. Npgsql Options normalization suppresses ambient PGOPTIONS and runtime guards reject switched current/session users. Actual PostgreSQL regression reproduces and rejects the prior unsafe-login path.

Completion retries are bounded and independent of registration capacity; server-slot headroom remains necessary. Orphan/stalled records have no expiry/force-close bypass. Drain timeout rolls back with access unchanged, so offboarding progress can require trusted instance fencing/recovery. Stop old API versions at rollout and fence old instances after any recovery/failover that might lose committed pending rows. API completion cannot recall proxy/network/client buffers. Future streams/exports/files require equivalent authority/completion treatment. Synthetic Kestrel/commit-loss/packaged identity tests are evidence for this scope, not managed fencing, live Okta/MFA, human operator identity, SLO or independent assurance.
