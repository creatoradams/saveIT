# ADR054: trusted compute task acquisition

Status: implemented; local synthetic SDK tests, native packaged acquisition and full CI pass. General CI's earlier cancellation-test startup race was corrected before verified source fd75fcb; exact evidence is tracked in progress. No AWS calls or launch evidence.

Replace caller-supplied task observations in the protected controller path with direct bounded SDK reads. Keep the offline ADR052 command explicitly offline, and ADR053 intent recording distinct from provider evidence. Use pinned official ECS and STS SDK clients in the existing deployment executable; the SDK owns SigV4. New clients require the current pinned Core patch. No new service or state store is introduced.

Operator AWS authority comes from exactly one protected temporary-session file, never CLI secret arguments, ambient profiles, environment credentials, task metadata, IMDS or a default provider chain. The public CLI is Linux-only and checks private owner-read permissions on the same open handle, with no group/other bits. Validate bounded original UTF8/EOF/fields/expiration; clear owned decoded buffers and acknowledge SDK managed-string lifetime. Independently configured scope plus regional STS caller identity must match the exact designated controller role/account before any ECS read. The role name is not proof of human/transitive isolation; external custodians remain trusted.

Use exact regional HTTPS destinations, explicit signing/configuration defaults, no proxy, redirects, compression, retries, host endpoint overrides or ambient telemetry. Own and bound complete raw responses before SDK unmarshalling. Reject duplicate JSON fields or unsafe XML/DTD/entity input; task validation must use original JSON so unknown fields cannot disappear in SDK model deserialization. Read only the four signed exact revision ARNs and reuse ADR052's complete derived contracts. Bound per-read/global deadlines, byte/depth/attempt counts and sanitize failures.

Acquired task metadata is a prerequisite, not a complete launch authority. Service/network/registry/configuration acquisition, durable side-effect intent, deliberate reconciliation of admitted approvals after expiry, exclusive ownership and Terraform handoff, restricted ingress/egress, health/drain and exact process/ENI fencing remain unfinished. No SDK client is exercised against AWS in account-free tests; synthetic handlers/native fixtures must stay labeled as such. All infrastructure remains unapplied and zero-count/null bootstrap contracts remain intact.

Pin deployment-only Core4.0.102.20, ECS4.0.111 and SecurityToken4.0.101.10; existing SecretsManager4.0.100.25 is retained. The Core update requires existing loader/native regressions. No ECR/EC2 SDK is added before its use. Native tests run the actual nonroot image against an INTERNAL-network provider, verify SDK signatures and TLS roots/names, preserve raw unknown task fields, actively count HTTP/CONNECT proxy and CSM traffic, observe client cancellation before late server fallback, and check EOF/private-file refusal and bounded owner-verified cleanup. The test-only SigV4 verifier is shared with the existing workload fixture; production always uses official SDK signing. Executed results are recorded in progress.

References: [official ECS SDK v4 client](https://docs.aws.amazon.com/sdkfornet/v4/apidocs/items/ECS/TECSClient.html), [ECS service API](https://docs.aws.amazon.com/AmazonECS/latest/APIReference/API_Service.html). Package versions and Core requirements were checked against NuGet's public flat-container metadata before pinning.
