# ADR 038: private API discovery and declared web/API network path

Accepted for implementation 2026-11-05; extends ADRs 033–037. This is unapplied private registry/network preparation, not client workload authentication, a runnable service, DNS/packet evidence or production readiness. Exact execution/reviews belong in progress.

Add a separate `private-discovery` Terraform root with the existing pinned provider, tracked lock and explicit account/region/cell/environment. Consume VPC/application-subnet/process-group metadata from `runtime-endpoints.runtime_network`, plus the new `ecs-tasks.api_transport` output derived from its actual configured web origin/API port/server-TLS declaration. Require the exact same-cell `https://api.<cell>.<environment>.saveit.internal:8443` contract. No arbitrary domains, plaintext ports, environment/command overrides, payloads, secret reads, IAM changes or launch-ready flags enter this root.

Check the explicit nondefault same-account/region/cell IPv4 VPC, DNS support/hostnames, one private CIDR association and no IPv6 associations. Require two distinct same-cell private IPv4 application subnets in distinct regional AZs. Check four distinct designated API/web/worker/deployment groups against scoped ARN/VPC/process tags. These are provider metadata predicates, not full route/SG/NACL/attachment/DHCP/resolver or IAM isolation proof. Existing endpoint/foundation guards remain separately required. Tags can be changed by trusted infrastructure administrators; another task attached to the web group can receive its network reach. Amazon resolver traffic is not contained by security-group rules.

Create only a private DNS namespace `<cell>.<environment>.saveit.internal`, an `api` Cloud Map DNS registry and the two standalone referenced-group TCP8443 directions: web egress to API and API ingress from web. No CIDR/prefix-list/general egress, reverse API initiation, worker/deployment API path, web ingress, plaintext path, task/service/instance/record registration or health updater is defined. Existing database/NFS/endpoint rules keep their separate owners; never introduce inline SG rules that overwrite those directions. The namespace and registry use prevent_destroy; registry force_destroy remains false. These source lifecycle guards are not immutable account controls.

Use IPv4 A/MULTIVALUE DNS with a fixed ten-second record TTL. Enable the private ECS custom health configuration, pinning its retired failure-threshold field to one despite the provider deprecation warning. Provider6.71 declares the field Optional/ForceNew and reads AWS's constant1 back into state; leaving it unset risks replacement churn blocked by prevent_destroy. Keep the narrow constant rather than ignoring drift. Public Route53 health probing is not a valid replacement. The pinned provider documentation deprecates the custom block while the ECS private-discovery contract still requires custom health; review that integration before provider migration. Actual ECS registry attachment/health updates are not implemented here. DNS health is not fail-closed admission: AWS can return up to eight unhealthy records if all are unhealthy, and client/negative caches and keepalive sockets can outlive this record TTL. Do not claim availability, measured failover, TLS workload identity or authorization from DNS.

Cross-root mock plans exercise actual endpoint-network and task-transport outputs flowing into this root, and reject shared web/API groups or a task-port mismatch. Boundary plans cover scope, DNS, subnet/AZ/process, origin/port/TLS and exact rule/DNS settings with distinct plan-time identities. Mock plans are declared reference/predicate evidence only; no AWS credential, resource, DNS query or packet is used. Application contracts, tenant/live membership/organization checks, RLS, audit/outbox, worker grants and response-drain protocol are unchanged. Web still has no secret authority and no new AWS action.

Before any service launch, implement client workload authentication and authenticated HTTPS ingress, restricted Okta egress/DNS controls, cluster/services and registry registration/drain/health binding, protected scheduler/jobs/PassRole/promotion, exact-byte/version-bound secret population, managed PKI/RDS/IAM/SG verification, redacted telemetry/quotas and operated fencing/recovery. No root may turn these metadata outputs into deployment approval. Preserve the entire enterprise inventory and all unimplemented capabilities.
