# ADR 036: public trust release files and pinned API transport configuration

Accepted for implementation 2026-11-05; extends ADRs 029/031/033/035. This is an account-free delivery contract and packaged implementation, not actual Secrets Manager injection, deployed PKI, protected promotion or a runnable cloud cell. Execution/reviews belong in progress.

Extend API's exact configuration fields with `Deployment__ApiTls__CertificateBase64` and `Deployment__ApiTls__CertificatePassword`. Keep every field on the same own configuration ARN and one canonical UUID version. Retain the current session protector and zero-to-four contiguous retired session pairs; maximum API selector count is now fourteen. Web still has no configuration secret or secret authority. No IAM action/resource/context/version boundary is broadened: execution already reads the entire own JSON secret. No value/version resource, payload input/output or secret lookup enters Terraform. Separate transport and session keys remain required operationally. The combined JSON, including passwords, connection, Okta secret, protectors and TLS PFX, must fit Secrets Manager's 64 KiB carrier; individual loader limits do not guarantee that. Protected population, aggregate payload preflight and actual injection/IAM/lifecycle remain unfinished.

Deliver public API and regional database CA bundles as explicit release inputs, outside the main source context. `prepare-public-trust.mjs` reads each source through one bounded nonblocking regular-file handle, validates it, and copies only those exact bytes into exclusive `api-ca.crt`/`database-ca.crt` output files plus a hash-only manifest. Output must be new/empty; the preparer neither overwrites existing files nor cleans arbitrary directories. Reject non-ASCII, private labels, mixed/trailing text, malformed or noncanonical Base64, decoded trailing bytes, duplicate roots, invalid validity, non-CA/missing constraints, wrong signing usage when present, weak RSA and unsupported EC keys. Canonical Base64 and exact decoded-to-certificate DER equality prevent a public label from carrying an appended private key. No input bytes, subjects, private values or parser exceptions are printed. An approved public certificate may itself contain extension data; this validator is not a general DLP/content-intent attestation.

Bound each bundle to 128 KiB and one-to-sixteen current CA certificates, RSA2048+ or NIST P256/P384/P521. .NET and Node use maintained X.509 parsers and share real acceptance/rejection regressions. The validators do not build chains or fetch AIA/network resources. Use the reviewed regional RDS root bundle rather than adding intermediate CAs or an indiscriminate global bundle; actual engine/region/root/rotation behavior still needs managed verification. No trusted CA or private key is generated for a real deployment by these scripts.

Docker's named `saveit-trust` build context replaces a scratch placeholder stage. Copy only fixed CA filenames, root-owned mode0444, into `/opt/saveit/trust`; web gets only `api-ca.crt`, .NET images only `database-ca.crt`. The ordinary source context still excludes `.local`, private key/PFX/PEM and secret files. The prepared named context contains only public certificate files and a hash manifest, never the private fixture/configuration directory. Building without a reviewed context produces deliberately unconfigured placeholders, which cannot satisfy strict task startup. Default image digests/inventories are not signatures or release approval.

Task definitions require separate canonical public API/database SHA256 metadata. Web receives `SAVEIT_API_CA_SHA256` and fixed startup `NODE_EXTRA_CA_CERTS=/opt/saveit/trust/api-ca.crt`; it validates the exact public file before loading Next or opening application traffic. Node consumes extra CA data before JavaScript starts; normal platform roots remain trusted. This is not exclusive anchor pinning. API/worker and both deployment CLI paths validate `Deployment__Trust__DatabaseCaSha256` once at startup and replace any original `Root Certificate` reference with the fixed baked database file while requiring VerifyFull. Existing GSS Disable, namespace/PGOPTIONS and non-owner/RLS guards remain. API readiness reuses that same normalized startup connection, without rereading/rehashing a bundle on every probe. Missing hash leaves existing explicit/local paths unchanged; declared cloud tasks always require the metadata.

Validation reads are bounded single-handle checks, but Node/Npgsql later open their configured paths themselves. The boundary is a read-only image, root-owned files and no trust-directory replacement mounts, not a same-handle consumption/mutation attestation. Privileged host/control-plane changes remain outside this guarantee. Avoid alternate CA mounts/ambient overrides in a managed release; preserve actual TLS hostname verification. A public hash is a declared input check, not provenance or protected promotion.

Packaged CI generates one synthetic CA before image build, prepares the public-only named context and retains that exact CA throughout smoke/recovery. The API transport PFX arrives through an ignored mode0600 fixture environment carrier, never CLI arguments, Terraform or image layers. Web no longer mounts a host CA; database clients do not rely on injected Root Certificate paths. The synthetic provider uses the same CA through SSL_CERT_FILE only in this isolated fixture; that is not evidence of independent provider/database PKI. Test readiness's original-configuration bypass separately with an invalid raw root/host and a working normalized real-PostgreSQL connection. Keep actual TLS CA/name/expiry/redirect/query-redaction canaries, startup hash/path/bypass rejection, read-only public-file ownership, retained-cookie/key recovery, access drain and database-outage checks on the same final images that are inventoried/scanned.

Task definitions now describe both delivery carriers, but do not prove their contents, populate secrets, publish approved images or launch services. Client workload authentication/mTLS, API intermediate-chain delivery, certificate issuance/renewal/rotation, real RDS trust/role behavior, DNS/discovery/network launch, restricted Okta egress, HTTPS ingress, protected jobs/PassRole/promotion, general redacted telemetry/quotas and operated fencing/recovery remain unfinished. No credentials, AWS apply, public deployment or enterprise scope reduction occurs here.
