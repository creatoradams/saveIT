# ADR 033: guarded application task definitions

Accepted for implementation 2026-11-03; extends ADRs 022 and 028–032. This partial compute root is unapplied and creates only three application task definitions, without a cluster, services, RunTask, scheduler or PassRole grants.

Define Linux x86-64 Fargate/awsvpc API, web and search-worker tasks independently. Require registry digest references in each workload's exact private repository, its separate task/execution identities and bounded secret selectors. Require both workload-identity EFS and operational-log binding-ready flags. These flags express declared contracts; they do not verify policy drift, transitive IAM authority, secret payloads, promotion or managed ingestion. Metadata lookups check exact existing roles, boundaries, repositories, logs and encrypted EFS access point. No secret version/value lookup or arbitrary environment/command input is accepted.

Use UID/GID 1654, read-only roots, dropped capabilities, bounded resource/stop/health settings and a writable private scratch volume. Docker image directory ownership and VOLUME metadata match the task mount. Only the API mounts the exact session-key EFS access point with IAM and transit encryption. Explicit shell-free ECS health commands supplement image healthchecks; ECS does not inherit image checks. API readiness uses literal loopback, no proxy/cookies/redirects, bounded headers/time and a configured Host value without allowing it to change the destination. It starts no host and opens no database connection itself. The running API's readiness endpoint retains its real database guard.

Fixed resource allocations are initial definitions, not capacity/SLO evidence. Task transport caps the explicit worker tenant list at 100 (the worker itself supports 1,000) and container JSON at 24 KiB, with headroom below ECS's 64 KiB task-definition limit. Operational logs use nonblocking delivery with a 4 MiB buffer: delivery outages can lose operational logs, while durable application audit remains in PostgreSQL. Digest syntax and metadata checks do not prove published images, signatures, vulnerability/license approval or protected promotion. The packaged synthetic stack exercises the changed Linux images, nonroot scratch writes and API/worker health during database outage; it is not Fargate evidence.

Private endpoints, restricted Okta egress, DNS/HTTPS ingress, authenticated encrypted inter-service transport, task launch networking, RDS CA trust delivery, cluster/services, authenticated migration/access jobs, protected scheduler/PassRole/promotion, collection/redaction/alerts/quotas, managed recovery and live AWS/Okta verification remain unfinished. The declared private web-to-API HTTP hop is a placeholder requiring that transport work before launch; private addressing alone does not protect cookies or content in transit. No credentials, cloud apply, image publication or paid service is needed to test these definitions with provider mocks. Preserve every enterprise backlog capability and all application authority boundaries.
