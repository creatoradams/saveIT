# ADR059: bound private route acquisition

Status: implemented and tested with synthetic SDK responses and producer mocks. Native and full CI for this delta remain pending. No AWS service calls or launch evidence.

`check-compute-routes` extends the signed security-group check with five fixed EC2 reads: exact VPC ID, its two DNS attributes, complete VPC-filtered subnet inventory and complete VPC-filtered route-table inventory. The locked SDK signs each query. Reuse its bounded native transport and original XML validation; no new dependency, endpoint override, arbitrary action, write, retry or pagination is exposed. The existing release, private session and regular-file assumptions remain. The complete sequence has25 reads, with160seconds overall/150seconds acquisition/10seconds stdin EOF/5seconds per provider read. Recheck cancellation, session and real approval time after every read. The internal expiry test clock can tighten but cannot bypass the real UTC check.

Require the signed same-account nondefault available VPC with a single canonical `10.x.0.0/16` primary association, no IPv6 and both DNS attributes true. The DHCP options ID is checked for syntax only; these reads establish no DHCP, Resolver or DNS policy. Require exactly the two signed application and two signed database subnets with no automatic public, IPv6, DNS64 or customer-owned addresses. The producer's four fixed `/24` offsets must be placed in two matching regional AZ name/ID pairs. Reject extras, duplicates, unsupported fields and continuation tokens. Free addresses are bounded metadata, not a capacity promise.

Require exactly the signed application and database tables plus the actual main table, identified by its intrinsic main association. All four subnets must be explicitly associated with the correct signed table, in associated state; the main table has no explicit subnet attachment. Each has its original active local route. Only the application table has the active prefix route to the exact signed S3 gateway ID. Reject public/default, propagated, blackhole, more-specific, replacement-local, alternate endpoint and unknown target authority. Main-table fallback, a substituted table or an omitted page cannot pass.

Use the same [frozen original XML](../../infra/terraform/cell-foundation/tests/compute-route-observations.json) in .NET and native fixtures. Mock plans compare the declared subnet placement, associations and application-only S3 gateway path against the fixture and signed IDs. The automatically installed route, intrinsic main table and actual response shapes are synthetic here. Tests include raw drift, exact official SDK query order, stop-on-first-invalid-response, original-byte positive cases and a valid final response at simulated approval expiry. Native cases retain exact request counters, no foreign/proxy/CSM traffic, target-observed deadline, bounded process cleanup and positive controls. Docker remains unavailable locally.

The fixed success output grants no provider or launch authority. No infrastructure resource/root, database/schema/API change, private result or tenant authority is added. Endpoint service/policy matching, independently reviewed canonical policy hashes, AWS ownership of the S3 prefix, DNS/Resolver and attachment checks remain open. Sequential reads are not atomic, and no drift prevention, reachability, ownership, drain or fencing is proven. All roots remain unapplied and service counts stay zero.
