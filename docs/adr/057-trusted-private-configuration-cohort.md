# ADR057: trusted private configuration cohort

Status: implemented; local tests and all48 native acquisition/full-CI checks pass at050ef1b. Exact evidence is in progress. No AWS calls, provider writes or launch evidence.

Extend the existing STS/task/parked-service/image sequence with exactly three Secrets Manager reads: API, worker and relay, each by independently approved full ARN and immutable version UUID. Reuse the existing pinned SDK, explicit temporary session and fixed native regional SDK/TLS transport. Web has no secret; migration/access/provisioning inputs are excluded. No stage selector, arbitrary endpoint/request, provider write or new dependency is exposed.

Validate the original response before SDK normalization. Exact ARN, friendly Name without the six-character ARN suffix, UUID and SecretString are required. Only bounded optional CreatedDate/VersionStages are allowed; decoded duplicate aliases, unknown fields and SecretBinary even null fail. Mutable labels never select authority: approved previous/unlabelled versions remain acceptable. Bounds are512KiB raw envelope,64KiB original decoded UTF8 payload and5seconds per complete HTTP read. No redirects/proxies/compression/retries/ambient telemetry; the official SDK owns signing.

Reuse the strict flat carrier, connection, PFX, current/retired protector and relay validators. Then check the cohort: matching configured database DNS host/port/database with exact runtime users; pinned database CA; canonical API/relay SAN names without CN/wildcard fallback; API server chain to the API roots bound by the approved relay payload; relay server chain to signed relay roots; relay client chain/pin to the signed API receiver policy. Chains use explicit purposes, CustomRootTrust, no downloads/AIA/revocation network. Only approved public CA bundles supply anchors; PFX extras never do. Unprovided intermediates fail closed.

Reject key reuse between the three private transport roles, between any protector and a transport role, and between any transport/protector key and a loaded API/relay/client/database trust-authority key. Canonical RSA SPKI hashes catch reissued certificates. Protector slots are not required to differ from one another; expired retired decryption support and the four-entry bound are preserved. Matching settings do not prove live database identity/roles/TLS, network possession, Okta/MFA or managed PKI.

The signed release format is unchanged. Its approved immutable relay UUID binds the payload's API CA hash under the existing provider/custodian trust model; this is not another independently signed root approval. CLI public trust paths are fixed. Deployment additionally receives root-owned0444 public client and relay roots through separate public-only named image contexts; no private key/configuration belongs there. API/worker/web private authority is unchanged. Placeholders/drift fail hash checks.

`check-compute-configuration` accepts the same signed-release-only stdin, independently configured public trust and private session file as ADR054. Limits:120seconds overall,110seconds acquisition,10seconds input EOF,5seconds per complete provider read. Its19 sequential reads are not an atomic provider snapshot or exclusive ownership. Recheck approval/session/cancellation after each private read and after cohort validation. Private bytes never enter output, files, arguments or Terraform; owned buffers clear on every outcome. SDK strings/JSON/PFX/configuration copies remain sensitive during process lifetime; clearing buffers is not full memory erasure. The private-constructed result retains only earlier public acquisition, and fixed CLI output is no launch approval receipt.

Tests use real synthetic private keys/chains, correct-name/purpose foreign issuers, raw versions/aliases/limits, database mismatches, key-role reuse, observed cancellation and actual approval/session expiry after responses. Native fixtures re-sign public bindings and deliver only synthetic private values to the isolated authenticated provider, retaining exact counters, verified foreign/proxy/CSM positive controls, deadlines and label-checked cleanup. Docker is unavailable locally; native execution awaits CI. See [progress](../progress.md) and [review](../reviews/2026-11-10-configuration-cohort-review.md).

No schema/API contract, infrastructure resource, running service or tenant authority is added. Network acquisition, protected signing/promotion/population, exclusive ownership/Terraform handoff, privileged-writer exclusion, effect intent/reconciliation, launch/drain and exact task/process/ENI fencing remain unfinished in the [section register](../configuration-compute.md). Actual secret/KMS/IAM/version selection and task injection require managed verification.
