# ADR 019: scoped document folders and independent placement

Accepted for the local core, 2026-10-30. Extends the existing plain-text documentation module and preserves all enterprise scope. Folders organize records; they never grant access.

## Model and authority

`DocumentFolders` stores tenant/organization/ID, nullable parent, bounded name, optimistic version and update time. Its parent FK includes tenant and organization. `DocumentPlacements` uses tenant/organization/document as its key, a nullable scoped folder FK, independent version and update time, and a scoped FK to the existing document. Both tables use forced RLS and tenant filters, bringing the total to **22 tenant tables**. The API has SELECT/INSERT and only the mutable name/parent/version/time or folder/version/time UPDATE columns. Keys cannot change and DELETE is denied; there are no cascades or archive/delete endpoints.

Every HTTP operation derives tenant/member context from the protected session, rechecks live membership and the current organization grant, and uses the authenticated tenant transaction. Viewers read; Editors create/rename/reparent folders and file documents with CSRF and expected versions. Missing/inaccessible parents, documents and folders remain 404. Folder IDs, paths and payload fields provide no additional authority. Folder-specific grants/denies, cross-organization filing and inherited permission administration remain unimplemented.

Existing documents start unfiled with placement version zero and no physical placement row. The first real move uses a plain INSERT at expected zero; duplicate first moves conflict rather than overwrite. Later moves update the placement version predicate. Returning to unfiled retains the row and advances its version. A no-op placement is rejected. Content edits/restores and filing operate on separate rows: filing preserves asset ID, title/body, content version, timestamps and immutable content revisions; restoration preserves the current placement. No historical folder identity/name is added to content snapshots, and this slice has no folder or placement revision-history/restore feature. Down removes the new triggers/tables and discards folder/placement data while leaving content intact; the tested empty-folder downgrade is not production rollback or backup assurance.

## Hierarchy concurrency and explicit limits

Hierarchy writes serialize through a transaction-level advisory lock derived from the tenant and organization, using the same PostgreSQL `hashtextextended(...,190019)` expression in the API and trigger. The API obtains it in a separate SQL statement before loading hierarchy state. The database's fixed-path SECURITY INVOKER VOLATILE trigger obtains it again, then runs separate scoped validation queries. There is no new elevated function or direct organization/grant write permission.

Both mutation triggers reject non-READ-COMMITTED transactions, enforce INSERT version 1 and UPDATE exactly old+1 without integer overflow, and reject changed keys. Separate queries in a [VOLATILE function](https://www.postgresql.org/docs/18/xfunc-volatility.html) obtain fresh snapshots; [READ COMMITTED](https://www.postgresql.org/docs/18/transaction-iso.html#XACT-READ-COMMITTED) plus the lock makes committed preceding moves visible. Real raw-role lock-wait tests verify that the second opposite move is rejected. A multi-row cyclic UPDATE rolls back the entire statement. Raw row locks acquired before the trigger can still deadlock with other callers; PostgreSQL must abort a transaction rather than allow a partial graph. No promise is made about uniform HTTP conflict codes for trusted raw SQL races.

The v1 bound is 1,000 retained folders per organization and eight folder levels. Counting stops at 1,001, recursive walks stop at nine levels, and reparent validates both destination ancestor depth and moved subtree height. Self/cycles, excessive depth/capacity and an ancestor chain that fails to reach a visible root are rejected. A path read similarly returns at most eight nodes or fails closed. Hierarchy validation depends on the configured tenant policy exposing the whole same-organization graph; partial folder ACLs require a separate design, not an additional row-hiding policy. This folder-specific safety bound does not implement general tenant quotas or establish measured scaling/SLOs. Bulk/deeper hierarchies and folder lifecycle remain future work.

## Reads, events and browser

Child folders and document metadata use UUID keysets, selecting at most 51 and returning 50 plus a cursor. Concrete-folder document pages filter scoped placements and inner-join current documents, supported by the composite tenant/organization/folder/document index; no execution plan or measured performance is claimed. Root/unfiled pages include legacy missing rows and retained nullable placements; the root anti/left join can scan more organization documents and remains an unmeasured scaling limit. Lists never select document bodies. A single bounded recursive query supplies current breadcrumb details. Every successful page/path/placement read, including empty pages, commits audit before serialization. Source/audit failures return no metadata/cursor; unavailable placement storage never becomes an invented unfiled result.

API folder and placement changes commit with numeric/opaque audit, metadata-only outbox and the existing trigger-enqueued search receipt. `DocumentFolder.Created`, `DocumentFolder.Revised` and `Document.Filed` schema-v1 events are explicitly acknowledged without projection changes; content versions remain unchanged during filing. Unknown events/schemas still dead-letter. Names/paths/body never enter audit/outbox. Worker guards reject new-table ownership, reachable writes and any new-table column reads; the worker gains no folder source authority.

The browser provides bounded breadcrumbs/children/documents, a paged destination picker, native create/rename/reparent/file forms, literal names and current-authorized document opening through existing asset navigation. Failed reads clear both collections and cursors. Initial requests cancel across context changes; explicit operations own their busy reservation, and late old-context denial cannot clear the new tenant/organization. Current-context denial clears the workspace; readers can explicitly reload organization choices. Saves clear old lists and show loading until refreshed data arrives.

Conflict recovery retains names/destinations and keeps Save blocked through failed reloads. Successful reload reads the current folder name/parent or placement plus its audited destination path before updating the expected version, and renders that state separately from retained choices. Retrying requires another explicit save. Escape/cancel returns focus to the opener; successful save focuses the persistent library heading. Backend checks remain authoritative regardless of UI state.

## Evidence and remaining work

Real PostgreSQL tests cover scoped FKs/RLS/column privileges, current grants/Viewer/member/CSRF denial, metadata-only column reads, filed/unfiled pages with unrelated noise, hierarchy depth/subtree/capacity, API and raw races, forced advisory waits, hidden ancestor failure, rollback at every write boundary, source/audit failure, migration preservation/unfiled defaults, worker grants/ownership/no-op/replay/unsupported schemas, and content/history/search preservation. Browser cases cover literal persistence/opening, conflicts/reload barriers/current-state review, bounded pages/destinations, loading/busy/retry/cancellation, Viewer/mobile/axe and denial recovery. Actual final results and review findings are recorded in progress, not inferred from test source.

No dependency or external service was added. Rich editing, document/SOP templates, folder history/lifecycle, attachments, deletion recovery, folder ACLs, bulk work, real Okta/cloud and independent enterprise assurance remain unfinished. The existing moderate development-tool advisory remains open; this slice does not claim production security, full accessibility or vendor parity.
