# ADR 037: offline protected configuration preflight

Accepted for implementation 2026-11-05; extends ADRs 031/036. This is a local input check, not protected population, a Secrets Manager client, a signed release or actual AWS/database/identity proof. Execution and reviews belong in progress.

The deployment image provides `check-configuration <api|worker|migration|access> <retired-count>` with the exact protected JSON bytes on redirected standard input. The count is a single canonical digit 0–4, zero outside API, chosen to agree with reviewed task/identity metadata. Web has no secret contract and is refused. Run before any connection/environment loading, host startup, database call or write; no connection, password, encoded PFX or payload belongs in arguments. Read at most 65,537 bytes and require EOF within a ten-second input deadline; only 1–65,536 original UTF-8 bytes pass. Whitespace and JSON escaping count toward this bound. No payload normalization, output file, payload hash or reserialization is produced.

Require one flat object of exact case-sensitive environment field names, all nonempty string values without NUL. Reject malformed UTF-8/JSON, comments/trailing commas, duplicate names including escaped aliases, extra/missing fields, path sources and noncontiguous or unexpected retired slots. API has six current fields and zero-to-four exact retired pairs; other workloads have one own connection. These match the existing pinned references without adding Terraform payload inputs/resources/lookups or IAM authority. This validator does not read a plan or prove the caller-selected count/ARN/version matches a deployed task. Protected population must later bind the exact reviewed bytes and metadata without reopening an untrusted mutable source.

Use existing offline connection policy: VerifyFull, no required GSS or arbitrary startup Options, plus a single DNS host, named database, password and workload-appropriate login syntax. Reject loopback/IP/multiple-host/local-socket targets, alternate root paths and verbose database error detail. API/worker names must be their existing fixed runtime roles; migration/access must use separate logins rather than known runtime, master or NOLOGIN operator/owner roles. Runtime guards and actual role/membership/TLS checks remain authoritative; syntax cannot prove privileges, DNS resolution or managed RDS behavior. Existing runtime normalization still supplies inert PGOPTIONS, GSS Disable and the public namespace.

Reuse the current ephemeral PFX loaders for RSA/strength/private-key/validity and server-purpose/DNS SAN validation. Current protector and transport must be valid; expired retired protectors remain usable for decryption. Compare RSA public key material to reject transport reuse of any current/retired session key, including reissued certificates around one key. This does not verify the intended API hostname/chain, private PKI issuance/intermediates, renewal/revocation, old-ring decryption or live Okta credentials. Ambient configuration is not merged. Public CA hashes/files and nonsecret runtime/task metadata remain separate ADR036 checks.

Output is a fixed success or failure line, with no original parser/provider exception or inner exception. Clear the owned raw byte buffer and dispose imported keys/certificates on every path; existing loaders clear decoded PFX bytes. Managed JSON/configuration strings cannot be reliably erased, so this is not a memory-zeroization guarantee. Run in the protected nonroot deployment environment without shell tracing, dumps, payload logging or retained test evidence. No real secret example is tracked.

Regression tests use synthetic keys and exact/overflow/Unicode/duplicate/alias/role/crypto/cancellation/error cases. Packaged tests send synthetic payloads over stdin to the same read-only nonroot deployment image with `--network none` before the database starts. They cover all four contracts, four retired protectors, exact/overflow aggregate limits, duplicates, wrong passwords, reused keys and refused web/count inputs. Child waits/output are bounded; cleanup verifies an exact container owner label. Image inventory/vulnerability checks still cover that same image. No credentials, AWS API, secret population or enterprise capability completion follows from these tests.

Next: protected population with exact-byte/version binding and authenticated custodian lifecycle, workload/client authentication and service discovery/launch/ingress, protected jobs/promotion, redacted telemetry/quotas and managed recovery. All enterprise scope and tenant/RLS/access-drain boundaries remain unchanged.
