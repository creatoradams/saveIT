# ADR 025: restricted operator access changes and durable response drain

Accepted for the bounded synthetic implementation, 2026-11-01 (migration timestamp 2026-11-02 UTC). Extends ADRs 001/002/010/022. Exact-commit general/packaged CI passed; evidence is in progress. Production operational/provider gates remain separate.

## Scope and authority

Add bounded private operator commands for existing-tenant member onboarding, active-state changes, organization-grant changes and organization-administration capability changes, with expected access versions and audited metadata inspection. Use a separate non-login PostgreSQL `saveit_access_operator` role reachable only by an explicitly provisioned operator login. It gets narrowly checked function execution, never schema/role ownership or general core-table reads/writes. Runtime roles must be denied membership in that role and direct/reachable execution of its functions. Operator authority comes from authenticated database credentials, not manifest tenant IDs or declared operator labels. Record actual database login plus bounded declared attribution; this does not attest a human IdP identity.

Checked definer functions fix their namespace, validate tenant/member/org sources and expected versions, and commit membership/grants, tenant-scoped access audit and a separate metadata-only control outbox atomically. There is no fabricated organization scope for tenant operations. This control outbox is not the search projection/consumer; generic delivery remains unimplemented. Do not include identity subjects, document text, secrets or free-form reasons in event metadata. Initial mapping remains exact issuer/subject; no email-based matching or automatic elevation.

Positive membership access versions and session epochs start at one without fabricating earlier access history. Epochs are signed into both identity adapters' cookies and checked against current membership on every protected request. Active-state transitions advance the epoch; reactivation cannot revive an old cookie. Grant/capability changes keep current-role checks and use expected access versions. Automatic organization-creator grants also advance the access version atomically; the latest checked create function locks the member for update before that increment. Existing epoch-less cookies must sign in again after rollout. CSRF-protected cookie clearing remains available to stale sessions. The one configured Okta issuer/tenant and all other enterprise identity gaps remain.

The three new tables (`AccessResponses`, `AccessAudits`, `AccessControlEvents`) bring the protected total to 28. Tenant/member and optional organization FKs remain qualified; event/audit references also include tenant/member. API and worker have no direct table/column reads or writes. Runtime guards reject reachable operator roles/functions and protocol-table grants, including PUBLIC and NOINHERIT paths. Only API receives response registration/completion function execution. The operator gets checked apply/inspect execution and release-marker metadata. Fixed role names are cluster-global: operator membership authorizes every database granting these functions unless separately restricted by CONNECT/per-database deployment boundaries. Use separate clusters/roles for separate operator trust domains; a supplied tenant ID is not an operator-credential scope restriction.

## Response drain

A session advisory lock alone is insufficient: losing its database connection releases the lock while a buffered protected response may still be executing. Use a durable per-request response record instead. A short transaction obtains the same member-scoped shared advisory lock used by the operator's exclusive barrier, rechecks active membership/subject/epoch and commits a pending record before allowing protected work. Store only tenant/member/request/instance IDs and timestamps/outcome, never routes, query strings, resource text or tokens. The lease record is operational state, separate from the existing business/revision/audit/outbox transaction.

An outer response envelope covers endpoint serialization and both sign-in adapters, including OIDC's authentication short-circuit. Only ASP.NET Core `OnCompleted` initiates closure, after server response finalization; middleware finally, RequestAborted alone, business/audit commit or endpoint-filter return is not completion proof. Completion persistence uses at most three independent two-second attempts and short delays; a transient failure retries only completion already known to have finished. Registration and completion use distinct pools (16/4 slots) so blocked registrations cannot consume completion's client-pool capacity. These do not reserve PostgreSQL server slots: real connection headroom/admission/capacity evidence remains necessary. Pending records survive lost connections/process failures. There is no time-based expiry that silently treats an uncertain response as complete. A content-free error identifies exhausted persistence; inspected pending diagnostics are capped, and each serving instance logs its fresh opaque instance ID once.

Access changes acquire the member's exclusive advisory lock before row locks, block new registrations, and wait a bounded interval for all earlier pending responses to close. Only then may they update access/epoch and commit/acknowledge. Registration, body/audit failure, completion uncertainty or undrained work must not produce a false successful revocation acknowledgement. Completion writes must not require the exclusive/shared registration lock, avoiding a drain deadlock. Completed-record retention/pruning must never delete pending records. Orphan resolution requires explicit privileged operational fencing of the original instance and audited recovery; an age threshold is not proof of fencing.

Registration/inspection gates allow three seconds; the exclusive gate plus drain allows five seconds. SQL command/connection deadlines bound other dependency waits. A drain timeout rolls back with access unchanged; it supplies acknowledgement safety, not guaranteed offboarding progress against stalled/orphan responses. An operator must inspect and arrange trusted instance fencing/recovery when necessary. There is deliberately no runtime/operator force-close or bulk-delete command. Completion prunes at most 32 already-closed records older than seven days for the same tenant/member, using its completion index and SKIP LOCKED.

READ COMMITTED is mandatory. VOLATILE PL/pgSQL uses separate SPI statements for advisory acquisition and each subsequent membership/epoch/pending observation; ordinary statements/CTEs can retain a pre-wait snapshot even at READ COMMITTED. Repeatable Read/Serializable are rejected. Tests observe actual waits in both orders, rather than inferring serialization from sleeps.

The guarantee concerns completion of API server response writes before an operator acknowledgement. Next.js/nginx and the network/client may subsequently deliver buffered bytes; these cannot be recalled. Privileged direct DBA changes or an incorrectly asserted operator fence are outside the checked protocol; ordinary runtime SQL/headers cannot claim that authority. New export/file/websocket/streaming consumers require explicit equivalent treatment before launch. Rollout must stop older API versions before enabling the operator acknowledgement protocol; schema checks alone do not change a running old process. Restore/failover that could lose committed pending records must fence ALL old API instances before access acknowledgements resume. Recovery of protocol state and instance fencing is a production operational gate, separate from the synthetic logical database drill.

## Required evidence

Use real PostgreSQL and actual restricted roles for scoped FKs/forced RLS, function/column grants, exact cookie epochs, atomic access/audit/outbox rollback, CAS/operator races, current role changes, reactivation and old-cookie denial. Observe actual database waits while protected JSON serialization is held; assert acknowledgement only after closure. Kill database sessions during an in-flight response to show a durable pending record prevents premature acknowledgement. Cover request abort, source/audit/commit failure, one-slot pools, bounded waits, cleanup retry/uncertainty, missing sources and orphan fail-closed behavior. Verify both identity adapters' final checks and packaged Production-mode existing-cookie offboarding/reactivation. Keep search least privilege/source authority and the complete product regression suite intact.

Implementation/test evidence is recorded separately. A synthetic loopback PostgreSQL frame proxy drops a real COMMIT acknowledgement after the server commits: registration does not retry, error-response completion closes its exact record, and an already-finished completion can retry idempotently. This is not managed failover evidence. Private operator credential issuance/rotation, human IdP attribution, actual cloud fencing, live Okta/MFA/offboarding, operational monitoring/recovery and independent assurance remain separate implementation/environment gates.
