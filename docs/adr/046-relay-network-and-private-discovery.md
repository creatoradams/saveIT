# ADR046: dedicated relay network and private discovery

Accepted 2026-11-08; extends [ADR038](038-private-api-discovery-and-network-path.md) and [ADR045](045-relay-endpoint-policy-admission.md). Reuse the existing endpoint/discovery roots, without another service framework, dependency or root. All resources remain unapplied; [progress](../progress.md) owns exact verification.

Add a separate default-false runtime-endpoints.relay_network_enabled switch. True requires the existing fully bound relay policy contract; policy admission alone creates no relay group. Enabled mode creates one distinct Process=relay group in the same VPC, four referenced interface-endpoint TCP443 ingress/egress pairs and regional image-layer prefix-list TCP443 egress. No inline ingress/egress, CIDR, database/NFS, public/default route or metadata rule is added. Existing single rule owners remain unchanged. The new nullable relay_network output contains only VPC, application subnets and group ID; the legacy four-group runtime_network and policy-only relay_admission contracts remain separate. Default false preserves existing resources and policy bytes.

Private-discovery accepts optional relay_network, checking the exact VPC/two-subnet set, a distinct non-client group and provider-reported ARN/account/region/VPC/Project/Cell/Environment/Process metadata. Invalid references fail rather than falling back to direct transport. Bound mode changes both existing API path rules to relay-to-API TCP8443 and adds only web-to-relay TCP8443 ingress/egress. The declared direct web/API pair is replaced. Foundation database, key-storage NFS and endpoint rule ownership remain separate. No task is attached to the group by this change.

Add a private relay A/MULTIVALUE Cloud Map registry in the existing namespace, ten-second TTL, custom-health threshold1, prevent_destroy and force_destroy=false, matching the protected API registry. Pin the deprecated threshold for the pinned provider's Optional/ForceNew readback; do not hide drift. No instance registration, ECS service or health publisher is created. DNS may return unhealthy records when every record is unhealthy; TTL is not a failover/cache/socket bound or an access gate. The output keeps relay origin and API target distinct. ecs-tasks.api_transport now derives the API-owned host and actual API container port, rather than coupling API identity to the web's destination environment variable. Existing task definitions and environment remain unchanged; future web-to-relay task binding is still required.

Null retains initial legacy web/API declarations. It is not an operated withdrawal, failover, revocation or fencing mechanism: switching an existing bound deployment to null can restore a direct path and protected registry removal can block planning. Fresh null-mode mocks do not prove that transition safe. Plan and review deployment transitions explicitly; never automate null as failure recovery.

Tests cover default/policy-only/explicit-network separation, complete endpoint path sets, unchanged policies, exact relay outputs, replaced API directions, protected registry settings, scope mismatches and actual staged producer-to-endpoint-to-discovery and task-to-discovery contracts. Provider mocks are declared contracts, not actual IAM, DNS, TLS, packet reach, health or withdrawal evidence. Security groups aggregate across attachments and cannot block Amazon resolver traffic; tags do not establish exclusive attachment or workload identity. No IAM grant, secret population, tenant authority or authentication change follows.

Next bind an isolated relay task and the web destination using these separate targets, then services/health/drain/ingress/restricted egress, protected population/promotion, scheduling/PassRole and operated fencing. Managed PKI, authenticated web workload intake, direct Logs customer CallerAccount compatibility, actual SG/DNS/IAM/KMS and recovery/capacity evidence remain gates. All146 enterprise inventory entries remain in scope.
