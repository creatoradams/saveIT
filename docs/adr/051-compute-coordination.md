# ADR051: durable core compute coordination

Status: implemented cooperative source with local real PostgreSQL evidence; full CI/native evidence pending. Not launch or fencing evidence.

Use the existing PostgreSQL authority store for a separate cell control row and append-only operation journal, not a new service or second state store. These operational tables contain no tenant content. They have forced RLS, owner-only policies and no runtime table/column authority. A separate restricted NOLOGIN compute operator reaches checked expected-version functions; API/worker credentials cannot reach that role or its functions. Forward migration remains seed-free; explicit insert-only initialization starts Parked.

The transition sequence is Parked→Starting→Running→Quiescing→CoreQuiescent→Fencing→Parked. Prepare binds a new never-reused generation and a reviewed plan hash. Runtime processes load generation once from protected launch configuration and never adopt a value from a request or database reconnect. State transitions, attribution and body-free journal append commit atomically. Uncertain commit acknowledgements are inspected, never automatically retried or reported successful.

Failed startup can transition Starting→Quiescing without activation. Liveness remains independent of database readiness and quiescence; Docker/ECS checks use liveness so an intentional drain does not itself trigger replacement. API/web expose separate startup/readiness routes; worker liveness requires a fresh valid heartbeat and readiness retains sticky tenant failures. Readiness is routing/operator evidence, not a restart trigger or fence.

Registration and every worker transaction take a shared global advisory gate before member/tenant/row locks. Checked operator changes take the exclusive gate. All waits are bounded; VOLATILE READ COMMITTED statements recheck state after waiting. Quiescing commits before pending responses are polled; CoreQuiescent requires a fresh persisted zero-pending check. Completion takes no compute gate or state/generation check and retains its separate bounded pool. Only server OnCompleted closes responses. No TTL, force-close, pruning or generation change bypasses an orphan response.

This is cooperative core/worker admission control, not credential revocation. Existing protected response records exclude anonymous work, web/relay buffers and key-ring activity. Local process admission/shutdown plus independently observed exact task/process termination remain required before whole-cell acknowledgement. A StopTask acknowledgement alone is insufficient. A privileged compute operator can invoke transitions; a protected controller must acquire/verify release metadata and actual provider observations before invoking them. No caller-supplied approval or fence boolean proves anything.

CoreQuiescent does not gate the separate access operator or migration/provisioning writers. Protected operation ownership must exclude those privileged writers before a snapshot or whole-cell stop acknowledgement; this primitive alone cannot establish that exclusion.

Null generation is only legacy/local compatibility when no control row exists. Once initialized, null/old generations cannot register work. The first rollout must stop older runtime versions which predate these checks. Recovery which loses protocol/control state requires independent old-instance fencing before reopening traffic; restoring a database cannot establish that fence. All managed verification and [whole-section acceptance](../configuration-compute.md) remain explicit.
