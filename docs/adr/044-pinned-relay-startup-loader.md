# ADR044: pinned relay startup configuration

Accepted 2026-11-08; extends [ADR043](043-isolated-relay-identity.md). This implements an isolated Linux startup read, not cloud compute, secret population or managed authorization evidence. Exact execution status belongs in [progress](../progress.md).

The existing deployment image accepts `serve-api-relay-secrets API_HTTPS_ORIGIN RELAY_HTTPS_ORIGIN SECRET_ARN VERSION_UUID`. Arguments contain public references only. The separate protected-stdin relay command remains available for synthetic/manual delivery. There is no private payload environment, file, stdin or AWSCURRENT fallback in the Secrets Manager command, no refresh/cache service and no new executable/project.

Validate the complete commercial ARN against the cell/environment relay naming contract and a canonical lowercase UUID before I/O. Derive region, expected same-account task-role ARN and the fixed regional HTTPS service endpoint from this reference. Retrieve credentials once from literal `http://169.254.170.2/v2/credentials/UUID`, accepting only the canonical ECS relative path. Require the exact task role, bounded nonempty temporary credential fields and a UTC expiry more than one minute ahead. This is validation of the metadata response, not STS/image attestation or proof of actual IAM authority. Reject alternate credential/profile/endpoint/CA sources and database/operator inputs.

Pin AWSSDK.SecretsManager4.0.100.25 (Core4.0.102.19) in the deployment project/locks. The SDK owns SigV4 and unmarshalling. Its generic container provider permits extra sources/retries and does not expose the required caller cancellation, so a small bounded native metadata GET supplies SessionAWSCredentials. There is no handwritten signer or refreshing credential provider. Explicit client settings disable configured endpoints, discovery, FIPS/dualstack, redirects, retries/clock-skew correction, default-mode probing, SDK HTTP caching, logging/metrics and OpenTelemetry output. A dedicated-process static initializer sets AWSConfigs.CSMConfig.CSMEnabled=false before the first SDK configuration/client. Legacy Client Side Monitoring has an independent environment/profile fallback and can emit session-token/error metadata over UDP; per-client logging/no-op telemetry alone is insufficient. The loader is internal to this CLI and test assembly, not a reusable SDK host component.

Own the two HTTP transports. Refuse proxies/cookies/decompression/redirects and any destination/method change; allow one credential attempt and one service attempt under one ten-second startup cancellation deadline, with two-second connects. Compare exact serialized URI strings because the SDK deliberately creates noncanonicalizing URI objects. Use HTTP1.1, connection-close, bounded headers, native system server trust/name/purpose, TLS1.2/1.3, offline chain building and no custom certificate callback. Revocation checks/downloads are disabled; this is not managed revocation assurance. No API private root or endpoint override is reused for AWS service trust.

Before SDK deserialization, require status200, no encoding/trailers, valid duplicate-free top-level UTF8 JSON and depth8. Read at most32KiB credential bytes and512KiB service-envelope bytes (including a one-byte overflow observation), independently of declared length. Reject any SecretBinary property. Require returned ARN/VersionId exactly; omit VersionStage and bound the original SecretString UTF8 to64KiB. Reuse the existing exact seven-field relay parser, PFX/DER pin, purpose/name/root-hash and distinct server/client RSA-key checks before opening a listener. Network-body waits share cancellation; bounded synchronous certificate validation is not a hard CPU/process wall-clock guarantee.

Clear owned response/payload byte arrays on success, failure and disposal; import private keys ephemerally and dispose startup clients before serving. Immutable managed strings, SDK-owned credential copies and native allocations cannot be guaranteed erased. Errors expose only the existing fixed relay failure; no provider exception, ARN, credential, secret, PFX/password or response body belongs in logs.

Regression tests use the real SDK signer/unmarshaller with controlled transports. Packaged tests execute the unmodified Linux command on a dedicated internal Docker link-local subnet: a test-only fixture owns the literal credential IP and regional service DNS alias, with a synthetic OS CA mount. No route to real AWS, public port or production endpoint override is introduced. Test successful TLS listening, wrong role/version, binary/oversize/redirect, stalled headers/body, untrusted service root and alternate/missing credentials. Poison proxies and CSM environment/default profiles; an acknowledged UDP positive control checks the listener before zero SDK-packet assertions. Test resource cleanup uses exact labels and bounded child/stdio ownership, including uncertain creation acknowledgments. These fixtures prove synthetic native behavior only, not AWS DNS/IAM/KMS/service compatibility.

Private endpoint admissions for the relay task's Secrets Manager calls and execution role's ECR/Logs calls remain the next account-free step. Referenced network/task/service bindings, public trust/digest binding and protected secret population/signing/promotion/PassRole remain unfinished. Web workload authentication, certificate rotation, health checks, drain and fencing also need implementation and managed verification. Preserve ADR043's direct Logs customer CallerAccount pre-apply compatibility gate. No AWS credential/API/apply or real secret is used here.
