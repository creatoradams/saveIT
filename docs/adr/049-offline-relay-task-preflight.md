# ADR 049 — Offline relay task preflight

Date: 2026-11-09. Status: implemented offline subset; execution evidence belongs in [progress](../progress.md). No protected launch, managed deployment or provenance approval is implemented.

ADR048 accepts exact task-definition revision ARNs as declared producer contracts while keeping every service at desired0. Before designing a privileged launch path, add a small read-only check for the isolated ADR047 relay definition in the existing deployment executable. Add no dependency, infrastructure root/resource, task activation switch or tenant authority. Other process definitions, service/network changes, authenticated intake, scheduling/PassRole, protected promotion and health/drain/fencing remain unfinished.

`check-relay-task` takes only redirected stdin: one object with `expected` public reviewed references and `observed` containing the original DescribeTaskDefinition response. Expectations require exactly accountId, region, cell, environment, taskDefinitionArn, image, configurationArn and configurationVersionId. Validate commercial-region/account/cell scope, positive canonical bounded revision ARN, exact deployment repository registry manifest digest and whole-secret ARN/UUID. Independently construct the relay's exact role, Linux/x64/Fargate,512CPU/1024memory, awsvpc, single nonroot1654:1654 readonly container, startup arguments, scratch volume, port, liveness and own-log contract; require ACTIVE and matching observed family/revision/ARN. Local Docker configuration IDs are not registry manifest digests.

Reuse only the existing owned bounded input mechanics; its flat configuration schema remains depth2/string-only. The new schema allows depth24 and at most64KiB original strictly decoded UTF-8 through EOF. The CLI has one ten-second input deadline including EOF. Reject duplicates including escaped aliases throughout every object, unknown semantic fields, extra containers/environment/volumes and every nonempty additional authority. Environment order and JSON object order are immaterial; environment names must be unique with exact name/value pairs. Startup/health arrays retain order. Unknown future AWS properties fail closed pending review.

Only explicit per-path returned defaults may be omitted or normalized: task enableFaultInjection=false; empty placementConstraints/inferenceAccelerators; ephemeralStorage.sizeInGiB=20; container cpu=0 and empty environmentFiles/systemControls/volumesFrom/ulimits; empty capabilities.add and logging secretOptions; scratch volume host={} and configuredAtLaunch=false. Nonempty host paths and all alternate volume kinds are rejected. No generic empty/null/false removal occurs. Supplied tags and service-computed registeredAt/registeredBy/requiresAttributes/compatibilities are opaque observations, never permission or source evidence; duplicates inside them still fail. Their contents are not authenticated or otherwise validated by this check.

Only fixed content-free success/failure is emitted, and the original owned input buffer is cleared on success/failure/late read. Parsed managed strings/JSON nodes may still contain drifted private environment content and are not erased; use an isolated protected process and do not persist or log incoming responses. No SDK initialization, credential discovery, network request, private configuration lookup, file output or deployment operation occurs in this branch. No payload belongs in Terraform/state, argv, Git or build input.

Both expectations and observations are supplied, unauthenticated data. Matching them proves only the implemented structural correspondence. It does not authenticate the expected source, response origin/freshness, actual image/CA/receiver-pin/private payload, registry existence, signatures/provenance/promotion, IAM/KMS, running task, service/network attachment or health. ECS RunTask overrides can change roles, commands/environment and resources after registration; this command does not inspect or prohibit them. It is neither launch approval nor a TOCTOU-resistant release control. Keep services at zero and implement trusted acquisition, protected release authority, override prohibition, bounded changes and operated drain/fencing separately before account-side deployment. Preserve the Logs CallerAccount compatibility gate and all146 roadmap entries.

Tests use the independent Terraform container fixture plus synthetic task envelopes, returned-default variations, drift/escalation/parser/bounds cases and actual CLI EOF/fixed-output checks. The packaged Linux suite runs the same command in a readonly nonroot image with networking disabled; this is synthetic execution, not cloud evidence. Security review and outstanding efficiency-review status are recorded with verification in progress.
