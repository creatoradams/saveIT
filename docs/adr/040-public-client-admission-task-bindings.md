# ADR 040: public client-admission task bindings

Accepted for implementation 2026-11-05; extends ADR039. This is public receiver metadata wiring in the unapplied task root, not a private client carrier, a runnable authenticated web/API deployment, managed PKI or launch approval. Exact execution/reviews belong in progress.

Add nullable `api_client_trust = { ca_sha256, leaf_sha256 }` to ecs-tasks. Default null retains required API client authentication with no invented CA hash/pins, so the receiver refuses startup. A populated object requires a canonical lowercase64hex CA-file hash and one-to-four ordered, distinct canonical lowercase64hex leaf fingerprints; reject empty/oversized/duplicate/null lists, null entries/CA and malformed or PEM inputs. Only API receives fixed CaSha256 and contiguous LeafSha256__0..3 environment names. Enabled remains fixed true and is not caller-overridable. No arbitrary environment, path, certificate bytes, private key, secret reference/value, resource lookup, IAM change or other workload metadata is added.

Take ca_sha256 from clientCaSha256 in the separately reviewed public client-anchor release manifest. Leaf fingerprints are SHA256 over the exact public end-entity certificate DER, not its PEM text, SPKI or an image digest. The administrator must review the intended peer and certificate lifecycle; Terraform validates strings and wiring, not certificate possession, chain, purpose, identity or the association with a published image. Runtime still checks actual baked CA bytes/hash, native chain, exact leaf/purpose and private-key possession. Separate public image contexts and existing receiver constraints remain authoritative; this metadata neither proves cryptographically disjoint trust bundles nor attests their contents.

A valid populated binding can allow the API receiver to start when its other runtime requirements pass. It does not supply a client to web: web still has no key, secret selectors or AWS authority, so no authenticated web/API path or healthy launch follows. Do not describe all bound APIs as startup-blocked, or interpret absence of that particular startup error as readiness. Null is an intentional unconfigured bootstrap, not a disabled-auth mode or a cloud deployment default to launch.

Pins are immutable task-revision inputs, not live revocation. Ordering maps exactly to the supplied list; reordering or changing it produces new task metadata, while existing instances retain their prior pins. Drain/fence/restart, certificate rotation/retirement, managed issuance/revocation, client delivery and operated recovery remain unfinished. Changing the binding cannot recall completed responses or supply tenant/user authority. All live membership, organization, forced-RLS, audit/outbox and response-drain rules remain unchanged.

Provider-mocked plans verify null, one/four ordered pins, exact API-only keys and malformed-boundary refusals. The actual workload-identity-module contract continues to verify unchanged task/execution identities and pinned secret selectors while public metadata is bound. These are declared configuration contracts, not AWS/IAM/injection or managed PKI evidence. Existing container JSON bounds, provider/action/tool pins and locks are preserved. No account credentials or apply are needed.

Next: implement a client carrier consistent with web's lack of secret authority, then authenticated ingress, service registry/health/drain and protected operations before authorized staging verification. A proxy TLS service cannot silently substitute for the actual-certificate receiver: AWS documents that Service Connect terminates TLS at its agents and application code does not see those TLS interactions. Any such alternative requires an explicit trust-boundary design and evidence, not an assertion that the existing API certificate check is satisfied.

Primary reference for that distinction: [AWS Service Connect TLS verification](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/verify-tls-enabled.html). No managed service choice, resource creation or cost commitment is made by this ADR.
