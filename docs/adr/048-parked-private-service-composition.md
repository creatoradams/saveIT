# ADR048: parked private service composition

Accepted 2026-11-09; extends [ADR046](046-relay-network-and-private-discovery.md) and [ADR047](047-isolated-relay-task-and-web-target.md). Add a downstream private-services root for separate service/state/release ownership. Services could technically live in private-discovery without a cycle; this separation keeps registry lifecycle distinct from later launch changes. Do not feed service/discovery outputs back into task targets. No runtime dependency or application authority change is added. All ten infrastructure roots remain unapplied; [progress](../progress.md) owns exact verification.

Compose three exact task_definitions ARNs, nonnull relay_task and both discovery outputs. Require canonical same-account/region/cell families and positive explicit bounded revisions, separate API/relay HTTPS8443 targets, same protected namespace and exact VPC/two-subnet set with distinct process groups. Reject latest/family aliases, operator services, crossed targets/registries and borrowed groups. Do not query container definitions or secret versions: those can persist drifted plaintext configuration. These task ARNs are declared producer contracts, not protected live task/image/payload inspection or launch approval.

Define one protected cluster and four fixed REPLICA services at hardcoded desired_count=0, with explicit FARGATE/platform1.4.0, ECS controller, bounded provider waits, circuit-breaker rollback settings, no forced deletion/deployment or Exec and no autoscaling/count/activation inputs or ignored drift. One own process SG and the same private subnet pair are the complete network attachment intent; public IPs are disabled. Migration/access stay outside this service set. API/relay alone attach their exact existing A registries, without SRV port fields; web/worker have no registry. No new SG/rule, LB, Service Connect/Lattice, task volume, capacity-provider strategy, IAM policy or PassRole grant is added. Container Insights remains disabled pending reviewed telemetry/redaction. Platform1.4.0 does not pin AWS's managed revision or prove runtime security/compatibility.

Read scoped VPC/private IPv4/two-AZ subnet/process-group metadata, exact private namespace and A/MULTIVALUE10s/custom-health1 registry settings. Select the Route53 zone by name/private_zone/vpc_id, then compare its returned ID to the namespace's hosted zone. The pinned provider skips VPC filtering when zone_id is supplied, so do not use that path as association evidence. The chosen query observes a matching VPC association, not exclusivity or lack of shared associations. The Cloud Map service's Optional-only tags field is populated from remote tags by the pinned provider; configure expected tags and retain returned-scope postconditions. Terraform mocks cannot override that field, so tag inputs do not prove returned-tag drift rejection. Mocks test computed metadata and declared query contracts; actual tags/associations/DNS/SG/routes/IAM still require managed verification.

Hardcoded zero means this source requests no tasks; it does not constrain account administrators, imported/existing services, RunTask or external schedulers. Applying/importing against an active service can scale it down without operated drain/fencing. Prevent_destroy and force_delete=false are source guards, not IAM enforcement, cleanup or safe withdrawal. No instance registration, health publication, successful deployment, drain, old-instance fencing or rollback has been demonstrated. Relay loopback liveness does not establish API mTLS readiness; DNS can still return unhealthy records and TTL is not a cache/socket/failover bound.

There are no IAM resources/grants here, but an authorized future cluster/service create can automatically create AWSServiceRoleForECS and enable ECS-managed ENI/discovery operations. Review that managed role, infrastructure PassRole/change authority, protected state and collisions/drift before any apply. Do not substitute an account-enforcement claim for desired0. Exact launch controls, authenticated web workload intake, restricted ingress/egress, protected image/configuration population/promotion and operator lifecycle remain engineering gates. Preserve the direct Logs customer CallerAccount compatibility gate and all enterprise scope.

Provider-mocked tests cover all service attachments and wrong-scope/revision/network/DNS cases, including actual staged store/relay/task/discovery outputs consumed downstream. These are declared contracts, not live service or health evidence. No AWS credentials/API/apply, registry publication or paid resources are used in tests. Next design protected launch/change controls and complete ingress/egress and operated health/drain/fencing before managed staging verification.
