# ADR053: durable compute release admission

Status: implemented intent persistence with local PostgreSQL evidence; full source/Linux/package verification pending. No provider actions or fencing.

Extend ADR051's existing operational journal rather than introducing another store or tenant table. A verified ADR052 release is admitted by one restricted compute-operator transaction: exact expected version, operation UUID and generation, signed-input hash, independently pinned signing-key identity and original signed public metadata persist with Parked→Starting. Unique operation and never-reused generation constraints remain. SQL rechecks digest, scalar bindings and freshness after acquiring the existing bounded global gate; only the protected .NET runner verifies the PS256 signature and independently configured trust anchor. The database function is not a cryptographic verifier, and the compute operator remains a trusted external identity.

Only checked functions reach journal release data; app/worker/access operators retain neither table/column reads nor function authority, including reachable PUBLIC/NOINHERIT grants. Human inspection returns body-free exact-operation status. The signed envelope is retained privately for future protected reconciliation, never printed in CLI status or put in tenant audit/outbox metadata. Existing journal rows are not backfilled with invented approvals. Failed admission/commit rolls back state and receipt together. A lost COMMIT acknowledgement is not retried or reported successful; inspect that exact operation instead. A short-lived token expiring cannot erase a durable admission or admit a second operation.

A stored row remains a trusted operator assertion. Future reconciliation must reverify the retained envelope against independently trusted current or historically approved public keys and its immutable operation, scope, generation and plan binding before constructing provider authority. It needs a deliberate already-admitted expiry policy; a stored hash or `admitted:true` is not sufficient. Neither raw operator SQL nor this status function provides cryptographic proof.

This is intent persistence, not trusted AWS acquisition, launch, image/configuration verification, protected signing/promotion, Terraform ownership handoff or a fence. Offline supplied observations remain distinguishable from provider evidence. ADR051's raw operator decisions remain cooperative primitives; future provider actions must require the admitted receipt and acquired metadata. Privileged-writer exclusion, exact stop observations and crash/partition/fencing drills remain unfinished in the section register. No response-protocol TTL, forced completion, pruning or credential revocation is introduced.
