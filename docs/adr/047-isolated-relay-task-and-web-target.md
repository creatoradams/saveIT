# ADR047: isolated relay task and keyless web target

Accepted 2026-11-09; extends [ADR044](044-pinned-relay-startup-loader.md) and [ADR046](046-relay-network-and-private-discovery.md). Reuse ecs-tasks and the existing deployment image. No new root, runtime dependency, IAM grant, service or account operation is introduced. All infrastructure remains unapplied; [progress](../progress.md) records exact execution evidence.

Add nullable ecs-tasks.relay metadata containing the bound relay-identity roles/configuration/operational_log/image_repository/binding_ready outputs, runtime-endpoints.relay_network, one exact deployment registry manifest digest and a reviewed web public CA-file SHA256. Require exact same-account/region/cell canonical task/execution roles, whole-secret ARN/lowercase version UUID, own encrypted finite-retention log, separate configuration/log keys excluding legacy log keys, and the staged deployment repository with exactly migration/access/relay execution readers. Require configured API public client admission. Read scoped role trust/boundary references, immutable encrypted repository, exact log/key/retention and relay group metadata; these do not simulate policy contents or prove actual/transitive IAM. Network subnet IDs here are format-checked declared references, not independently queried or attached.

Define the relay separately from the three application tasks: one Linux x86-64 Fargate/awsvpc container, UID/GID1654, read-only root, dropped capabilities, no privilege/interactive/TTY, 30-second stop timeout and one private scratch volume. No EFS, injected secrets, database/operator configuration or arbitrary environment/command input is accepted. Entry point is fixed to dotnet SaveIT.Deployment.dll; arguments select serve-api-relay-secrets with separate canonical API/relay HTTPS8443 origins and the exact whole-secret ARN/UUID. Only the relay task's existing SDK read retrieves private configuration; execution keeps its separate image/log role. Operational logs retain a bounded4MiB nonblocking buffer and can be lost; they are not a tenant audit archive. Resource sizing remains unmeasured.

Bound mode changes only web's destination and public CA-file hash in the existing application definitions. Web remains keyless with its original role, empty secret injection and fixed root-owned public file path. A reviewed web image may contain a different public server-CA bundle than the deployment image's outbound API roots, using the existing per-image public-only build context. Ordinary Node platform roots remain enabled; a file hash is not exclusive trust-anchor or leaf pinning. Neither metadata nor these mocks prove that the web image contains the declared bundle, that it validates the actual relay certificate, or that the protected relay client leaf matches a current API receiver pin. Protected population and managed PKI/handshake evidence remain gates.

Keep API-owned transport independent of web's destination. Derive canonical origins from the cell; discovery consumes task outputs downstream rather than feeding discovery back into tasks. The legacy three-entry task_definitions output is unchanged; separate nullable relay_task carries the task reference and declared network/transport targets for future service bindings. No ENI/SG attachment, cluster, registered instance, scheduler/PassRole or service is created.

The image gains quiet probe-api-relay with exact arguments only, before any SDK/database/application configuration. It sends one HTTP1.1 GET to literal127.0.0.1:8080/health/live, no credentials/cookies/proxy/redirect/decompression, connection-close, bounded headers, one-second connect and one three-second cancellation deadline through headers and body EOF. Only200 with an actual empty body and no encoding or announced/received trailers passes. No host/port/environment override or output is added. This is local process liveness after startup, not current API connectivity, certificate usability, managed role authorization or readiness. ECS runs this shell-free command with its own five-second timeout; no shell/curl package is added to the chiseled image.

Tests retain null compatibility, compare the whole relay container against an independently authored fixture, reject crossed/foreign/bootstrap/version/repository/key/network/CA metadata, check provider-reported mismatches and consume actual staged store/relay/task/discovery modules. Real loopback probe tests include status/body/header/trailer refusals, header/body stalls, active default-proxy control and exact CLI dispatch. The native Linux loader fixture executes the actual probe under poisoned proxy configuration, requires quiet success and rejects mixed arguments without extra metadata/secret reads. Synthetic checks are not AWS/IAM/TLS/attachment proof.

Null is initial compatibility, not safe operated withdrawal: task-definition deregistration does not stop/fence existing tasks, recall loaded certificates, drain responses or revoke old API pin sets. Existing network/discovery null transition limits still apply. Next implement separately reviewed private service/registration/health/drain/network attachment and restricted ingress/egress, protected population/image promotion/scheduling and old-instance fencing. Authenticated web workload intake, direct Logs customer CallerAccount compatibility, managed IAM/KMS/PKI/recovery and all 146 enterprise inventory entries remain open according to their individual status.

Primary references: [ECS health-check command semantics](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/healthcheck.html) and the pinned [task-definition provider](https://github.com/hashicorp/terraform-provider-aws/blob/v6.71.0/website/docs/r/ecs_task_definition.html.markdown).
