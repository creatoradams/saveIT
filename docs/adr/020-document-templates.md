# ADR 020: versioned plain-text document starters

Accepted for the local core, 2026-10-31. Extends ADRs 007/019; the full enterprise roadmap remains in scope. This is not enterprise completion or production assurance; actual verification is recorded in progress.

An organization owns a metadata-only `DocumentTemplate` head and immutable `DocumentTemplateRevision` snapshots containing exact name, title, plain text, lifecycle, actor and timestamp. Publishing, including archive/reactivation, increments the expected head version and appends the snapshot with audit/outbox/queue in one transaction. Three new forced-RLS tables bring the total to 25. Scoped FKs, restricted mutable head columns and append-only snapshot/origin grants retain tenant/organization boundaries. Invoker triggers enforce initial/incremented versions, matching snapshots and a deferred matching-snapshot requirement for every publication. No new elevated functions or direct identity authority are introduced.

Metadata and history pages contain at most 50 rows and never select body content. Exact immutable snapshots and provenance require separate audited reads under live membership/organization roles. Audit/source failure withholds results; an unreadable origin never becomes a fictional no-template result. Archived history remains readable. Names/content are plain text, bounded to 160/50,000 characters, with no executable placeholders, dynamic expansion or HTML rendering. Existing body/request limits apply.

Creating from a starter requires a current Editor, CSRF, a current scoped asset, an active template and its exact explicitly reviewed current version, plus the user's reviewed title/body. The API obtains a scoped head `FOR SHARE` lock before reading lifecycle/version and holds it through the outer commit; concurrent publication/archive waits or finishes first and causes a stale preview to conflict. A raw-role origin trigger independently checks current active version under the same row lock. This does not create a synchronous grant-revocation barrier; ADR 002's limits remain.

Creation appends the normal document, initial content revision, immutable `DocumentTemplateOrigin`, audits and normal schema-v1 `Document.Created` invalidation atomically. The origin has scoped document/template-revision FKs, a document-initial-revision FK and CHECK version=1, and one row per document. It means **started from a reviewed starter with editable content**, not proof that final text equals the template. The actual initial content snapshot records edits. New documents start unfiled at virtual placement version zero. Later template publication, content edits/restoration and filing never rewrite origin or placement. Existing/manual documents have no fabricated origin. There is no template reapplication, document upgrade, bulk generation, template restore or deletion endpoint.

Worker reads/writes/ownership on all three tables remain denied, including reachable column grants. Only known schema-v1 template metadata events are acknowledged without projection changes. New documents follow ordinary current-source indexing of their reviewed final body; unpublished template content is not indexed. Provenance is separate from DocumentDto, content/revision versions and search contracts.

The browser will provide explicit authored SOP starters, version review, archive/reactivate, bounded lists/history, reviewed document creation and current-state conflict reload. Failed reads clear output, owned requests coordinate global busy/cancellation, current-context denial clears the workspace, and unsuccessful conflict reloads retain the Save barrier and drafts. Actual validation/review/CI results belong in progress after execution.

Cross-organization starters, rich editing/files, executable variables, checklists/workflows/approvals, template history comparison/restore, permission administration, cloud deployment and independent security/performance/accessibility assurance remain unimplemented. Built-in starter text is an editable synthetic outline, not an approved operational procedure. No new dependency or external service is required.
