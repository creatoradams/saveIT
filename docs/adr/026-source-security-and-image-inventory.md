# ADR 026: account-free source security and image inventory

Accepted for implementation 2026-11-01. Extends ADR 022. Execution status belongs in progress; workflow definitions alone are not passing evidence or production approval.

Use pinned Gitleaks with upstream default rules against every reachable ref in a nonshallow checkout. Disable inline allow comments, redact matches completely and emit aggregate counts only. Preserve upstream path/stopword exclusions explicitly: this is pattern detection within the scanner's scope, not proof that every file or arbitrary secret is covered. The repository adds one exact historical prose fingerprint exception, never a blanket baseline. A runtime-generated, never-issued token canary must be detected and redacted despite an inline allow comment. Scanner timeout, shallow history, malformed results and tool failures fail the job. Worktree/untracked files and unreachable/nonfetched history are outside the full-history command.

Run pinned official CodeQL security-extended analysis separately for C#, JavaScript/TypeScript and Actions. Build C# under instrumentation; retain generated SARIF as restricted-duration workflow artifacts. An explicit parser fails on high/critical security scores (>=7), any effective error-level result, failed execution, unknown rule metadata or malformed output. Medium/low results remain visible for triage; a passing threshold does not certify absence of vulnerabilities. No broad source/path/query suppression is introduced. Dependency audits remain separate, including existing moderate development-tool reports. The security workflow has no cloud authority; only CodeQL jobs get security-events write. Untrusted pull requests run without repository/cloud secrets or deployment credentials.

Pin Gitleaks/Syft versions and official release-asset SHA256 checksums for Linux/Windows x64. Verify the bounded archive before extracting only its named binary. This checks integrity against reviewed pins; it does not verify publisher signatures. CodeQL action/linked CLI and other workflow actions are immutable commit pins. Tool updates require review, canaries and CI.

Inventory the same four nonroot application/process images that passed packaged checks, excluding the synthetic identity target. Attach the exact source SHA as an OCI label. Require a canonical positive numeric UID (bounded signed-32-bit range), rather than infer identity from a username. Generate Syft native JSON and explicitly selected CycloneDX 1.6 together, validate the pinned formats and binding metadata against a real synthetic Docker-save archive, and bind native image configuration ID, explicit source name/configuration-digest aliases and both revision labels across formats. Reject mismatched inventories or empty packages/components. Record source SHA, local configuration IDs, package counts and SBOM byte SHA256 values in a release manifest. Images and evidence stay ignored locally; only short-lived inventory artifacts are uploaded, not application images or backup/key material.

Local Docker configuration IDs and Syft local manifest digests are not registry manifest digests, signed artifacts, attestations or protected promotion. SBOMs are inventories, not vulnerability scans. Registry publishing, digest-based promotion, publisher/build provenance verification, container vulnerability/license policy, branch/environment enforcement, runtime servicing, actual cloud/Okta verification and independent assurance remain gates. No workflow mints cloud credentials or deploys resources.
