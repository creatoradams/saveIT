# ADR056: trusted image configuration acquisition

Status: implemented; local combined tests pass. Source52b3cc8 passed native packaged execution, but source security rejected a fake-provider authentication bypass; the separate forbidden-destination fixture remedy awaits full verification. No AWS calls or launch evidence.

Before provider writes, acquire and hash the exact platform-image manifest and configuration for each of the four signed image references. Extend the existing deployment executable with the official pinned ECR SDK. Reuse the explicit private temporary session, exact STS/controller identity and fixed native SDK/TLS transport. Add no service, state store, provider write or Terraform activation input. Keep task/service checks and the immutable signed source/image bindings.

Use BatchGetImage with explicit account/repository/digest and only Docker-v2/OCI platform manifests. Preserve the original JSON envelope/manifest string and independently hash its exact UTF8 bytes. Indexes, foreign URLs, extra image/failure entries, unknown semantic fields and schema aliases fail closed. Descriptors bind one bounded configuration and bounded canonical layer digests; these reads do not download/scan/verify layer bytes. Multi-platform index/attestation selection remains separate reviewed work.

Use one bounded SDK GetAuthorizationToken followed only by exact same-account/region registry-v2 configuration blob GETs. Validate the returned registry endpoint, canonical bounded Basic token and expiry; never follow arbitrary download URLs, redirects or host overrides. The16KiB encoded token/32KiB envelope bounds are local fail-closed compatibility limits; AWS specifies no fixed token maximum. The token is a provider bearer credential, may outlive the temporary session, and is never persisted, emitted or forwarded elsewhere. Owned decoded buffers are cleared; managed credential/header strings and parsed JSON copies remain sensitive for process lifetime. This is not a human credential lifecycle or revocation mechanism.

Hash/size-bind the original configuration blob before parsing. Require Linux/amd64, canonical nonroot1654, fixed working directory/entrypoint/command/volumes, known environment and source/revision labels. Check inherited startup authority, not only task overrides. Unknown execution/environment authority fails closed. Source/label/hash correspondence does not prove reproducible source-to-binary provenance, signature, vulnerability scan, license approval or protected promotion. Final application-image inventory and scanning remain separate gates; web bundle cataloging completeness remains open.

Actual ECR response/default/IAM/registry compatibility requires managed verification. Synthetic tests use isolated endpoints and invented registry digests, including configurations derived from actual packaged image inspection where specified. They never become registry publication, promotion, task-launch or fencing evidence. Full controller, exclusive ownership transfer, privileged-writer exclusion, network/configuration acquisition, drain and exact task/ENI fencing remain unfinished.

`check-compute-images` consumes only the independently anchored signed-release stdin and private temporary-session file from ADR054. It checks STS, all four tasks and the initial parked cell first. Input EOF is bounded10seconds; the whole command100seconds, acquisition90seconds and each complete HTTP read5seconds. Manifest responses allow256KiB, decoded manifests/configurations64KiB and at most64 compressed-layer descriptors/10GiB declared total; no layer is fetched. Current platform policy accepts only gzip Docker-v2/OCI manifests, not index/attestation selection, foreign layers or alternate compression. These are local compatibility restrictions, not claims about every ECR image.

The five pinned AWS packages remain deployment-only; ECR4.0.102.3 uses existing Core4.0.102.20. No browser/API contract, database migration, service or Terraform resource is added. A future base-image servicing change must update the independently derived known environment/startup policy and pass actual packaged-image checks. Full layer/provenance/promotion approval and web bundle inventory completeness remain explicit gates.
