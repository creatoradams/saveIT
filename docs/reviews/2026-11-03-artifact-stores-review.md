# Private image and operational log store review

Two user-requested agents inspected the bounded ADR 032 delta independently and read-only: artifact-stores definitions/tests, the existing workload-identity contract, the log-key remedy and associated ADR/README guidance. Neither edited files, ran tests, used AWS credentials/APIs or applied resources. Current primary AWS/provider documentation informed their service/provider assessments. Primary execution is recorded separately in [progress](../progress.md).

Both agents identified the same concrete integration gap: encrypted PutLogEvents' documented caller path requires KMS authority, while the existing execution boundaries admitted only configuration-secret decryption. Matching repository/log ARN names alone did not establish that caller permission contract.

The remedy adds optional exact five-key log binding to workload-identity. Bound execution roles get only own-key crypto through regional Logs with exact group context, plus separate exact-key/via-Logs DescribeKey without encryption context. Complete explicit-deny boundaries cap other actions/keys/direct/wrong-context requests, scope the existing secret/version conditions to configuration keys and reject reusing any configuration key as a log key. Web gains only own-log KMS authority, with no secret/query permissions; task boundaries and null bootstrap remain unchanged. Future compute must require both log and EFS binding-ready.

The actual alternate-module test consumes store output key references and checks declared crypto/description grants as well as image/log/role contracts. Ten additional identity cases cover complete bound policy shape, missing/wrong/cross-workload predicates, invalid/colliding inputs and the production namespace/long-secret-ARN policy sizes. Primary-agent mock results are 40 identity plus 31 artifact-store/contract plans passing. These are configuration/narrow predicate checks, not an IAM simulator.

Both agents rechecked the source remedy and updated documentation without remaining actionable correctness/efficiency/security findings in this delta. Trust/admin privileges, six-key costs, retention expiry, no automatic image expiry and unfinished signing/promotion/collection/compute remain explicit. Actual KMS/ECR service grants, IAM enforcement, encrypted PutLogEvents/query behavior, key/policy drift, managed retention/recovery, independent assessment and enterprise readiness remain unverified. This review is not whole-repository assurance, a safety certification or production approval.
