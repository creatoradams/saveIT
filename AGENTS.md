# SaveIT repository guidance

Source-security/inventory changes preserve pinned tool/action hashes, full nonshallow reachable-history scanning, redaction and disabled inline allow comments. State inherited scanner exclusions and keep only reviewed exact false-positive fingerprints. Keep real scanner canaries, fail-closed SARIF severity/error handling and same-image native/CycloneDX bindings, explicit source/configuration-ID aliases, pinned output format and canonical positive numeric UIDs. Unsigned inventory hashes are not registry digests, signatures, vulnerability scans or promotion evidence.

Read `docs/project-brief.md`, `docs/architecture.md`, `docs/progress.md` and relevant ADRs before architectural changes or completion claims. Preserve all enterprise scope in `docs/backlog.md` and `docs/feature-parity.md`; unimplemented capabilities stay visibly unimplemented. Use original SaveIT branding and synthetic data.

Never derive tenant authority from request headers/payloads alone. Preserve live membership/organization checks, transaction-local PostgreSQL context, forced RLS, tenant/organization FKs and the non-owner runtime-role guard. Do not replace real PostgreSQL integration tests with an in-memory provider. Business writes, revisions where applicable, audit and outbox must commit atomically. Development identity stays opt-in and impossible in Production.

Run appropriate .NET tests, `npm run typecheck`, `npm run build`, `npm run check:ignore` and relevant Playwright tests. Regenerate OpenAPI/TypeScript when contracts change. Keep lockfiles, migrations, `.terraform.lock.hcl` when providers exist and sanitized environment examples tracked. Never commit real environment files, state/plans, secrets, test evidence or local DB files.

Document restoration appends a new revision and preserves old snapshots. Keep current Editor/expected-version checks, audited historical comparisons, bounded diff/pages, source/reason provenance constraints and atomic revision/audit/outbox tests. Never place historical content or restore reasons in audit/outbox metadata. Asset/deletion recovery and managed/offsite backup restoration remain separate unimplemented work.

Asset relationships never grant access. Preserve both tenant/organization-qualified endpoint FKs, forced RLS, live organization roles, audited bounded reads and lifecycle/duplicate concurrency checks. Removal retains the row and assets/documents; only lifecycle columns are updatable. Search explicitly acknowledges schema-v1 relationship events without indexing them; unsupported events/schemas still dead-letter, and worker column-level core write grants must fail its startup guard.

Organization name history is API SELECT-only. Preserve checked create/rename functions, locked membership-derived actors, fixed origins, exact persisted snapshots and atomic history/current/grant/audit/outbox/queue writes. Backfill only actual current versions, keep fresh Seed attribution and existing-seed idempotence, and restore predecessor functions before dropping history on downgrade. Every bounded history page requires current organization authority and durable read audit. Worker history ownership, column reads and reachable writes remain denied. History never grants rename, restore or permission-administration authority.

Document folders never grant access. Preserve scoped parent/document/folder FKs, forced RLS, column-limited writes, the identical tenant/org advisory lock in API and VOLATILE invoker trigger, READ COMMITTED-only mutations and eight-level/1,000-folder bounds including moved subtree height. Keep raw multirow/lock-wait tests. Placement versions are independent of content versions; filing never rewrites content/history/search, and restoration preserves current placement. Audit reads before serialization and commit mutations/audit/outbox/queue atomically. Worker folder/placement reads and writes remain denied; only known schema-v1 metadata events are acknowledged. Preserve sticky conflict barriers through failed reloads and show fetched current state separately from retained choices. Folder history/lifecycle/ACLs, bulk work and measured root/unfiled scaling remain unfinished.

Document templates use immutable scoped snapshots and append-only origins pinned to document revision 1. Preserve the source head FOR SHARE lock before current lifecycle/version reads through creation commit, per-publication deferred snapshot checks, scoped FKs/forced RLS and atomic document/revision/origin/audit/outbox/queue writes. Provenance means reviewed starter with editable text; it is not an exact-copy guarantee. Later publication, restore and filing preserve origin/placement. No origin is invented for legacy/manual documents. Keep body-free audited pages, exact-source fail-closed reads, worker table/column exclusions, ordinary Document.Created indexing and known schema-v1 template metadata acknowledgments. Failed conflict reloads retain drafts/barriers and clear stale current reviews; historical inspection restores keyboard focus after unlocking. Comparison reads at most two scoped immutable snapshots and current head version only, filters before bounded line pages and audits numeric versions before returning any output. Comparison never refreshes write authority; retain real source/current/audit/commit failure tests and deferred keyboard focus. Template restore/reapply, dynamic variables and bulk generation remain unfinished.

The search worker is implemented; its tenant-scoped consumer receipts and derived PostgreSQL projection must remain separate from core authority. Search must join current grants/source before fields, previews or pagination and fail closed on source/audit failure. Preserve replay, backoff, dead-letter, rebuild and least-privilege tests. Application-cell Terraform, OpenSearch, generic external event delivery and connectors remain unimplemented scaffolds/roadmap work. The separate state-bootstrap definition is unapplied and tested only with provider mocks; preserve exact account/role inputs, explicit deny boundaries, native lock permissions and tracked provider locks. Do not imply enterprise identity, vault/AI, cloud deployment, measured SLOs, compliance or verified vendor parity works until implemented and evidenced. Record limitations and progress accurately.

Deployment uses separate seed-free forward migrations and insert-only bounded initial provisioning under the isolated non-login migration owner; runtime roles must never reach it. Preserve owner-only backfill policies, forced tenant RLS, exact migration-history checks, fixed public namespace, explicit GSS Disable/Require rejection and verified remote database TLS, schema-CREATE/elevated-role guards and atomic provisioning. Trust forwarded protocol only from bounded configured peers. Preserve nonce/no-store runtime web behavior, nonroot images, bounded worker connection/command/cancellation waits, deadline retry/backoff and sticky per-tenant health. Synthetic external identity/container checks are not live Okta, cloud or managed recovery evidence.

The synthetic packaged recovery drill restores into a separate database/key volume with writers quiesced, original ownership/grants retained, hash/count checks and old-cookie/history/tenant/search/write verification. Keep inner shells fail-fast and cleanup restricted to label-verified fixture volumes. This is same-cluster/retained-role/CA logical recovery evidence, not managed/PITR/offsite/KMS or measured RPO/RTO. Asset/deletion recovery remains separate work.

Access operations use a separate restricted NOLOGIN operator role, exact expected versions and body-free tenant access audit/control events. Preserve all 28 forced-RLS tables and runtime denial of operator roles/functions and protocol-table/column privileges. Cookie epochs come from live membership in both adapters; active-state transitions must prevent old-cookie revival. Creator grants advance AccessVersion atomically. Protected/sign-in responses register durable pending records under the shared member gate; operator changes take the exclusive gate before core row locks and drain before commit/acknowledgement. Only server OnCompleted can close records, with separate bounded completion capacity; no TTL, RequestAborted-only/finally closure, force-close or pending pruning. Keep VOLATILE READ COMMITTED post-wait snapshots, observed wait/uncertain-COMMIT/Kestrel/least-privilege tests and fail-closed timeout behavior. API completion does not recall proxy/client buffers. Lost protocol state during recovery requires old-instance fencing; operated fencing/recovery and human operator credential lifecycle remain unimplemented gates. Suppress ambient PGOPTIONS with the explicit inert one-space Options value and reject current/session login mismatch; an empty Options round-trips to null.

Image vulnerability changes preserve exact SBOM/report hash and source/image/revision bindings, same verified seekable stdin handles, pinned Grype tool and explicit config, cleared host GRYPE overrides, fresh update checks (zero skip interval), validated DB checksum/age, and high/critical/unknown/unfixed blocking. Actual ignored matches/coverage alerts fail closed. Grype threshold exit code 2 differs from tool failure code 1; keep real scanner/exit tests and lower findings visible. A base-only scan is not the final application-image result; custom Node/native-library combinations require packaged Linux version/TLS/auth/recovery/health checks. No vulnerability exception, signature, license approval or promotion claim follows from passing scans.
