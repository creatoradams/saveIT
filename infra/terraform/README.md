# SaveIT infrastructure preparation

The separate downstream [private-services root](private-services/README.md) composes exact task/discovery outputs into a cluster and four hardcoded zero-count private service definitions (ADR048). Separate service/state/release ownership keeps later launch changes away from task/registry lifecycles; this is an architectural choice, not an inherent requirement for a tenth root. Only API/relay attach registries; every service declares one own SG and private subnet pair. No task, instance, health publication or actual attachment exists. Protected activation/change/ingress/egress, operated health/drain/fencing and managed proof remain gates. Future AWS create can auto-create its ECS service-linked role, despite no IAM resource/grant in this root; review that scope and PassRole/state/change authority before apply.

The [relay-identity root](relay-identity/README.md) adds unapplied isolated relay task/execution roles, configuration/log metadata and staged exact artifact-stores deployment-reader admission (ADR043). Null bootstrap denies all AWS actions; bound reference checks are not live IAM or launch evidence. Legacy five-workload contracts and four-repository/five-log/six-key counts remain unchanged. The exact-version startup loader (ADR044), optional endpoint filters (ADR045) and separate network/discovery opt-in (ADR046) are implemented; optional isolated relay task/web-target definitions and liveness are implemented (ADR047), while private services/network attachment and managed verification remain unfinished; direct Logs customer CallerAccount availability must be resolved before apply.

The [private-discovery root](private-discovery/README.md) adds an unapplied private API namespace/registry and initial standalone web/API TCP8443 rules (ADR038), with optional dedicated relay registry and replaced web/relay/API paths (ADR046), consuming guarded task-transport and endpoint-network reference outputs. It grants no AWS/secret authority and launches/registers no instance or service. DNS health is not fail-closed access and SG metadata is not workload identity. Client/ingress authentication, registration/health/drain, service launch/protected operations and managed verification remain gates.

The [runtime-endpoints root](runtime-endpoints/README.md) adds unapplied private ECR API/DKR, Logs/configuration interface endpoints and an application-only regional S3 image-layer gateway (ADR 034). Foundation now exports separate application/database route tables. Endpoint filters add no IAM/task/tenant grant. Pinned provider route filtering, SG/DNS drift and actual IAM/presigned/ingestion behavior remain unverified; no account resource or running service exists.

The [ecs-tasks root](ecs-tasks/README.md) adds three unapplied guarded Fargate application task definitions (ADR 033). Concrete EFS/log identity bindings, exact digest/secret selectors and nonroot/read-only scratch/health settings are checked with provider mocks and an actual alternate-module contract. It creates no cluster/services/launch/networking or PassRole. Private endpoints, egress/ingress, encrypted inter-service transport, trusted forwarding/RDS CA delivery and protected operations/promotion remain unfinished.

The [artifact-stores root](artifact-stores/README.md) now defines unapplied private immutable ECR repositories and protected finite-retention operational log stores, matching the workload-identity references through real alternate-module mocked plan checks (ADR 032). It creates no images, logs, identity grants, promotion or compute. Six declared rotating KMS keys isolate registry and per-workload log encryption. Runtime/publisher/operator enforcement and actual cloud behavior remain unverified.

The parent application root remains a non-provisioning scaffold with no provider/backend. `terraform fmt -check` and `terraform init -backend=false` / `terraform validate` check that scaffold when Terraform >=1.9,<2 is installed. The separate [state-bootstrap root](bootstrap/README.md) now defines private versioned KMS-encrypted state storage with a pinned AWS provider/lockfile and credential-free mocked tests. Those definitions are unapplied; no cloud resource exists.

Before an actual AWS apply, resolve [ADR 004](../../docs/adr/004-deployment.md), cloud accounts, budget, regions/residency, networking and remote-state key/access controls. Application core/API, worker, private data, storage/KMS, identity, monitoring and regional-cell modules still need implementation and tests. State bootstrap uses Terraform 1.13.5 and AWS 6.71.0 with signed Windows/Linux checksums in its tracked `.terraform.lock.hcl`; keep locks tracked as providers are introduced in further roots. State, plans, backend overrides/configuration and local secret tfvars are ignored; sanitized examples remain tracked. Native mocked plan tests are configuration evidence, not AWS IAM enforcement, applied infrastructure or recovery evidence.

The separate [cell-foundation root](cell-foundation/README.md) now defines isolated private networking and protected managed-PostgreSQL intent with account-free mocked plans (ADR 028). It remains unapplied and is not a runnable application cell: compute, HTTPS ingress/restricted egress, workload secrets/keys, operator reach/fencing, promotion and actual managed verification remain unfinished. No account credentials or secret values enter its source/examples.

The separate [key-storage root](key-storage/README.md) defines only private persistent encrypted session-key-ring storage (ADR 030), with exact API-role/access-point/TLS/mount-target boundaries and mock plans. No filesystem is created or mounted; task roles/compute/secret references, actual managed permissions/multi-replica behavior and backup/restore/fencing verification remain unfinished. It owns one standalone NFS egress rule on the foundation API security group, without changing foundation rule ownership.

The separate [workload-identity root](workload-identity/README.md) adds unapplied isolated task/execution roles, explicit-deny boundaries, four protected configuration-secret metadata containers and pinned version references (ADR 031). Its fail-closed bootstrap avoids the API-role/EFS creation cycle; metadata-checked binding later enables exact API mount/write. No secret values enter Terraform. Compute/registry/log resources, ingress/restricted egress, protected operator/promotion, telemetry/quotas and actual managed authorization/recovery still require work.
