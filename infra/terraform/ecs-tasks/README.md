# Guarded application task definitions (unapplied)

Bind relay-identity outputs plus runtime-endpoints.relay_network, an actual deployment registry manifest digest and reviewed web CA-file hash; [the synthetic shape](tests/relay-binding.json) is not a release or launch approval. Bound mode requires configured API public client admission and changes only web's destination/CA hash among the existing three application definitions. The relay receives no injected secrets, EFS or DB/operator configuration: its own task role runs the exact-version SDK loader, while its distinct execution role pulls/writes its own image/logs. The separate relay_task output declares future network/transport bindings; task_definitions remains three entries.

The shell-free probe-api-relay health command checks fixed loopback8080 process liveness with a three-second deadline through body EOF; it does not prove current API mTLS readiness. No cluster/service/registration or ENI/SG attachment is created. Subnets are format-checked declared references here; only relay SG metadata is read. Discovery remains downstream of task-owned API transport, avoiding a dependency cycle. A different reviewed public web CA bundle can use the existing per-image build context; hashes do not prove its association with the digest or actual relay certificate/receiver pin. Null/deregistering a definition is not operated rollback, drain, revocation or fencing. No managed proof follows.
